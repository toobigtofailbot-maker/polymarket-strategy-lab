## Proposed proof mechanism and no-fork default

**Primary:** source-faithful, isolated, host-owned evidence at actual *pinned* `AIAgent` child creation/completion boundary — not source-side LLM text. The host wrapper (existing `ExternalHermesCliBackend` or a narrowly tested equivalent) must observe the trust boundary directly: parent/task intent, child session/subagent identity, effective enabled+disabled actual tool names, launch/completion/failed terminal and result digest. It must bind these records atomically to a unique execution nonce and consumer source hash; child/self-reported summaries are data only. In-process dynamic hook injection is acceptable only if pinned signed source and controlled isolation prove that a child or model cannot overwrite/forge the trusted audit channel. A stdout parser of model JSON is **not** adequate. A public version bump or custom fork is **not** preauthorized.

**What could block the pin:** CLI one-shot has deliberately limited externally returned telemetry; internal child events may be available but not exported by the stock subprocess. Need exact proof of a secure host-owned hook/FD/path and child session completion observability. If no small supportable mechanism exists within the declared path budget: issue `PINNED_CHILD_WITNESS_UNAVAILABLE`, disclose inspected functions/failed tests, and compare (a) minimal audited pinned upstream patch/broker, (b) strictly isolated newer pinned Hermes version, (c) two separate controlled one-shots **as temporary functionality only**. Option (c) cannot close mandatory original `R3-05` genuine `delegate_task` requirement unless Karl explicitly changes scope. Do not allow infinite feasibility spikes or bluff true external witness.
