# Local Generated Artifacts

## Purpose

This document records the WP6 local generated-artifact cleanup incident and the guardrails that prevent project-local security-tool output from being staged or committed.

Generated local artifacts have no execution authority and must never be treated as source, runtime dependency integration, trading logic, scan approval, or live-trading authorization.

## Incident Summary

GitHub Desktop showed thousands of local files under `.venv-security/Lib/site-packages/...` on `main`. These files were generated by WP5 project-local security tooling and were not intended for commit.

## Observed Local Issue

Before WP6 branch creation, the local checkout was on `main` at WP4 merge commit `6992be5b7c3f77ba5b895997c282a5f5a9f1636e`, while the required WP5 merge commit `432e95fb937170aae7419a33e6be7c1fa6bdf2be` was not yet present locally. `git status --short` showed only:

```text
?? .venv-security/
```

## Investigation Commands Run

The following commands were run before cleanup:

```powershell
git branch --show-current
git status --short
git status --short -- .venv-security tools/.bin tools/security/.cache security-scan-output
git ls-files -- .venv-security tools/.bin tools/security/.cache security-scan-output
git diff --cached --name-only -- .venv-security tools/.bin tools/security/.cache security-scan-output
git check-ignore -v .venv-security/
git check-ignore -v .venv-security/Lib/site-packages
git check-ignore -v tools/.bin/
git check-ignore -v security-scan-output/
```

After cleanup and fetch, the Remote Main Sync Gate was run:

```powershell
python tools/git/preflight_sync_main.py --required-commit 432e95fb937170aae7419a33e6be7c1fa6bdf2be --required-file .gitignore --required-file docs/security_tooling_status.md --required-file tools/security/setup_project_security_tools.py --required-file tools/git/preflight_sync_main.py
```

## Tracked/Staged/Untracked Status

Facts observed before cleanup:

- Branch: `main`
- `git status --short`: `.venv-security/` was visible as untracked.
- `git ls-files -- .venv-security tools/.bin tools/security/.cache security-scan-output`: no tracked files were reported.
- `git diff --cached --name-only -- .venv-security tools/.bin tools/security/.cache security-scan-output`: no staged files were reported.
- No generated artifact path outside the allowlist was reported.

Because no tracked or staged generated files existed, deleting the allowlisted generated local directory was safe.

## Ignore-Rule Status

Facts observed during investigation:

- `git check-ignore -v .venv-security/` reported a `.gitignore` rule for `.venv-security/`.
- `git check-ignore -v tools/.bin/` reported a `.gitignore` rule for `tools/.bin/`.
- `git check-ignore -v security-scan-output/` reported a `.gitignore` rule for `security-scan-output/`.
- `git check-ignore -v .venv-security/Lib/site-packages` did not report a match at that moment.
- After syncing to WP5, `.gitignore` contains `.venv-security/`, `tools/.bin/`, `tools/security/.cache/`, and `security-scan-output/`.

## Likely Root Cause

The evidence proves that the local checkout began WP6 from stale `main`: local `main` and `origin/main` were still at WP4 before `git fetch --all --prune`, while WP6 required the WP5 merge commit. After fetch, `origin/main` advanced from `6992be5b7c3f77ba5b895997c282a5f5a9f1636e` to `432e95fb937170aae7419a33e6be7c1fa6bdf2be`, and local `main` was fast-forwarded.

The most likely cause is that `.venv-security/` was created by WP5 security tooling while the local checkout or GitHub Desktop view was not yet fully synchronized with the merged WP5 repo-truth and ignore state. The investigation did not prove that any `.venv-security/` files were tracked or staged.

## Cleanup Performed

Only this allowlisted generated path existed and was removed:

```text
.venv-security/
```

The cleanup did not use a broad repository clean command. `tools/.bin/`, `tools/security/.cache/`, and `security-scan-output/` were checked but were not present.

After cleanup, `git status --short` was clean.

## Prevention Controls Added

- `tools/git/cleanup_generated_artifacts.py` removes only allowlisted generated artifact directories and refuses to run if generated files are tracked or staged.
- `tools/git/preflight_generated_artifact_guard.py` fails if generated artifacts are missing ignore protection, visible in status, staged, or tracked.
- `tools/security/setup_project_security_tools.py` now refuses to create or reuse `.venv-security/` unless ignore protection is active and the path is not tracked or staged.
- Repo-truth docs now require generated-artifact guard checks before future WP branch creation.

## What To Do If This Happens Again

1. Do not commit or stage generated artifact files.
2. Run:

```powershell
git status --short -- .venv-security tools/.bin tools/security/.cache security-scan-output
git ls-files -- .venv-security tools/.bin tools/security/.cache security-scan-output
git diff --cached --name-only -- .venv-security tools/.bin tools/security/.cache security-scan-output
```

3. If any generated artifact file is tracked or staged, stop and request explicit remediation.
4. If files are untracked and under the allowlist only, run:

```powershell
python tools/git/cleanup_generated_artifacts.py --apply
python tools/git/preflight_generated_artifact_guard.py
```

5. Run the Remote Main Sync Gate before creating any WP branch.

## Safety Statement

WP6 cleanup and guardrails add no trading logic, venue API integration, runtime dependency integration, external repo source code, credentials, wallet material, live-trading path, executable `src/` module, global package installation, or system package installation. Live trading remains disabled.
