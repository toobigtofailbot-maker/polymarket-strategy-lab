## Incident Provenance

After WP175J / PR #183 merged, the one authorized S10-GATE-H1 real research
invocation ran exactly once and ended `FAIL_RUNTIME_CONTRACT` / `EXIT_CODE_NONZERO`
(exit code 1, not timed out, stdout not truncated, usage evidence MISSING, validated
research NONE, 0 sources). S10-GATE-H1 single authorized real invocation consumed = 1.
Two offline diagnostics followed with zero network/provider/Firecrawl activity:
DIAG-01 = `ROOT_CAUSE_NARROWED_NOT_CONFIRMED`; DIAG-02 =
`PREACCOUNTING_PATHS_PASS_ROOT_CAUSE_STILL_UNRECOVERABLE`. DIAG-02 proved every
testable pre-accounting startup path passes for the frozen provider/model/toolset,
and that a caught in-agent failure would have written a usage file — so the decisive
signal (the child's stderr) had been intentionally discarded by the sanitized
boundary, leaving the exit-1 mechanism unrecoverable from retained evidence.

## What WP175K Fixes

WP175K hardens ONLY the observability gap. The external backend already captured
bounded child stderr in memory but discarded the bytes before the controller could
preserve any diagnostic context. WP175K adds a deterministic in-runner sanitizer that
keeps a SMALL, secret-scrubbed, path-scrubbed diagnostic TAIL excerpt
(`MAX_SANITIZED_STDERR_EXCERPT_BYTES` = 4096) and records usage-file presence, while
still discarding raw stderr. Redaction removes named/JSON secret assignments,
Authorization/Bearer/Basic material, PEM private-key blocks, known token prefixes
(`sk-`, `ghp_`, `github_pat_`, `xox*`), JWT-shaped tokens, URL userinfo, and URL
query/fragment material; local filesystem identity (Windows/UNC/home/temp paths) is
scrubbed to `<PATH>`. A conservative residual check fails closed to no excerpt
(`BLOCKED_UNSAFE`), and any sanitizer fault fails closed (`SANITIZER_ERROR`); neither
changes process-exit classification or introduces a retry.
