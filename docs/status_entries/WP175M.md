## What WP175M Fixes

WP175M fixes the contract BEFORE model generation. It does NOT normalize or infer
substantive research after generation: `evidence_map`, `sources`, `completeness`, and
`cross_category_assessment` are never mapped onto canonical fields; a wrong substantive
schema still FAILS CLOSED.

- `models.py` owns the canonical draft contract. The private `_DRAFT_LIST_FIELDS` is
  promoted to the public `DRAFT_LIST_FIELDS`; a canonical ordered
  `DRAFT_REQUIRED_TOP_LEVEL_FIELDS` places `schema_version`/`request_id` first, then the
  authority flags (`advisory_only` first), then the substantive research fields, so the
  sanitized "first missing field" is deterministic. Validator-aligned bound constants and
  sorted confidence / source-class vocabularies are shared by the validator and the
  generator.
- `build_research_draft_output_schema(*, expected_request_id, max_sources)` produces a
  deterministic JSON-schema-like mapping: `type: object`, every canonical required field,
  the exact `schema_version` and `request_id` embedded as constants, each authority flag
  `const: true`, `research_summary` non-empty with the validator-aligned max length,
  `confidence_label` enum, each list field an array of bounded strings,
  `falsification_checks_performed` non-empty, and `source_references` min 1 / max
  `min(max_sources, MAX_SOURCES_ABSOLUTE)` with required `url`/`title`/`source_class`. The
  generated required set is IDENTICAL to the validator's required set (STOP
  CONTRACT_VALIDATOR_DRIFT); it invents no constraint the validator does not enforce.
- `policy.py` bumps `PERMANENT_SYSTEM_INSTRUCTION_VERSION` to
  `hermes-research-system-instruction/1.1.0` and states the envelope's
  `draft_output_schema` is authoritative, the final response is exactly one JSON object,
  canonical field names must be used exactly (no aliases such as `sources`, `evidence_map`,
  `completeness`, `cross_category_assessment`), every authority boolean is exactly `true`,
  and substantive fields must reflect real research (never fabricated). The full field
  list is not statically duplicated in prose. `HermesResearchEnvelope` gains
  `draft_output_schema`, included in `as_mapping()`, `to_query_bytes()`,
  `to_prompt_string()`, and `envelope_digest`, plus a `draft_output_contract_digest`.
- Authority-boolean injection is DECLINED: all draft authority flags remain MODEL-OUTPUT
  REQUIRED and must be exactly `true`; the wrapper never injects them.

## Sanitized Failure Observability

`inspect_research_draft_structure(raw)` returns a `DraftStructureDiagnostics` carrying only
static canonical field-name tokens and fixed statuses (`AVAILABLE` /
`UNAVAILABLE_INVALID_OUTPUT`; the controller default is `NOT_REACHED`). It never retains a
rejected value, arbitrary model key, research text, URL, or provider payload. For the H1
#3 shape it reports present = `schema_version`, `request_id`; missing = all remaining
canonical fields; first missing = `advisory_only`.

## Finding G — Exact Contract/Validator Alignment (follow-up)

Side11's exact-head review of interim head `6bd57f3` found the generated output contract
was not yet EXACTLY validator-equivalent, violating WP175M's own `STOP
CONTRACT_VALIDATOR_DRIFT` requirement:

- `research_summary` and source-reference `title` used only `minLength: 1`, but the
  validator rejects whitespace-only strings (`value.strip()` non-empty), so a single
  whitespace character satisfied the schema yet failed the validator.
- the URL schema invented a validator-absent `format: uri`, and its `pattern`
  (`^https://`) was both weaker than and case-sensitive relative to the validator's
  case-insensitive `_URL_RE`.

The correction shares the exact remaining primitives between the validator and the
generated schema, without redesigning the contract and without broadening or narrowing
validator behavior:

- `DRAFT_NON_WHITESPACE_PATTERN = r"\S"` — a JSON-Schema search-style regex meaning
  "contains at least one non-whitespace character", used by the validator's
  `research_summary` and source-title non-whitespace tests AND embedded as the `pattern`
  for both fields (`minLength: 1` retained, already implied).
- `DRAFT_SOURCE_URL_PATTERN = r"^[hH][tT][tT][pP][sS]://[^\s/$.?#].[^\s]*$"` — the single
  source of truth: `_URL_RE = re.compile(DRAFT_SOURCE_URL_PATTERN)` (the explicit
  character-class HTTPS prefix preserves the former `re.IGNORECASE` accepted set without a
  flag a schema consumer cannot see), and the generated URL schema uses the SAME pattern
  with `maxLength` only; `format: uri` is removed.

The required-field set, receipt 1.3.0 fields, provider/model evidence semantics, draft
diagnostics, and failure precedence are unchanged; the H1 #3 alternative-shape fixture
still fails `DRAFT_FIELD_MISSING` at first missing `advisory_only` and the valid synthetic
contract fixture still passes.

Frozen request-id literal proof: the ignored PUBLIC H1 #3 request file
(`local_data/s10_gate_h1/h1_3_*/h1_3_request_public.json`) is not present in this
worktree, so `FROZEN_H1_REQUEST_IDENTITY_LOCAL_PROOF: SKIP_WITH_REASON`
(local public request evidence unavailable). The request-identity algorithm and
`public_fields()` are unchanged, so the frozen id remains structurally reproducible.
