## Endpoint and GET-only boundary

- Gamma `GET /markets` (public, no-authentication) and optional CLOB
  `GET /book?token_id=...` (public, no-authentication) only.
- Exactly one possible Gamma request; optional CLOB books bounded to at most 20.
- The existing conservative local guard is consulted before the Gamma request and
  before every book request; a guard denial makes no call, and a book denial
  rejects the whole run before any persistence.
- No Data API, `POST /books`, authenticated endpoint, `get_health`, `get_market`,
  or trading method is used.

## Empty-store initial seed and fail-safe ordering

- A new network population requires an empty WP163 record store; a non-empty store
  makes zero network calls and rejects with `POPULATION_RECORD_STORE_NOT_EMPTY`.
- Seed records are `PRIMARY_ASSERTION`/`NORMALIZED_ACCEPTED` with empty lineage and
  no supersedes; no cross-run lineage is invented.
- A single captured UTC timestamp is `observed_time`, `ingestion_time`, and
  manifest `effective_time`; deterministic content-addressed `snapshot`/`ingest`
  run identities are independent of API response order.
- Records persist through WP163 before the exact validated batch is registered
  through WP162: records first, reference second. A registration failure after a
  committed append never deletes records and returns
  `POPULATION_RECORDS_PERSISTED_REGISTRATION_FAILED` with `recovery_required=True`.

## Offline recovery behavior

`recover_initial_polymarket_public_registration` performs zero network activity,
constructs no client, and never writes records. It re-registers a store proven to
be exactly one valid unregistered/retryable WP164 seed (1..45 records, provenance
and identity checks, single snapshot/batch/observed==ingestion time), re-sorts into
WP164 order, re-runs `validate_record_batch`, and re-registers through WP162 using
the unique ingestion time.
