## Scaling, baseline convergence, and capacity

- Only the current page's records are registered as ordinary ids; direct lineage
  parents are an explicit external-parent set already committed by an earlier manifest
  entry, so physical history may grow to the WP163 4096-record horizon while each
  capture's current and direct-parent contexts each stay bounded at 256. `WP165-D001`
  is resolved within the current physical horizon; `WP162-D004` is resolved for the
  registered external-parent context.
- Before any network the physical WP163 record-id set must EXACTLY equal the union of
  every registered reference's ordinary ids; a strict superset blocks new network and
  advises recovery. Capacity gates (WP163 4096, WP161 256 entries/references,
  current-page 256) run before any client call; over budget rejects with
  `SCALED_CAPACITY_EXCEEDED`.
- Current records are appended (records first), then the current delta is registered
  (reference second). A post-append registration failure returns
  `SCALED_RECORDS_PERSISTED_REGISTRATION_FAILED` with `recovery_required=True`,
  preserves the validated `next_cursor`, and never deletes records.

## Keyset and double opt-in

- `GET /markets/keyset` is documented (checked 2026-08-30) but not live-probed by this
  repo and is `verified=False`. Real keyset use requires BOTH `allow_network=True` and
  `allow_documented_unverified_keyset=True`; a lone `allow_network=True` is rejected
  before any client construction or GET. Only that double-opted-in path constructs the
  client with `allow_unverified_endpoints=True`, and only the documented keyset call
  relies on it; the CLOB book endpoint remains already repo-verified. One invocation
  performs at most one keyset page (<=100 markets) plus at most 20 books; the response
  `next_cursor` is returned for a later manual invocation with no automatic loop.

## Offline recovery behavior

`recover_scaled_polymarket_public_registration` performs zero network activity,
constructs no client, and never writes records. It is a valid
`SCALED_ALREADY_REGISTERED` no-op when the store already converges; otherwise it
re-registers exactly one genuine scaled page (1..120 records reconstructed
object-for-object from the registered prior state with the run identity recomputed
using `config.after_cursor`, and every direct external parent already registered)
through the WP162 lineage-delta adapter. A forged, multi-page, drifted, or
after_cursor-mismatched orphan set fails closed as `SCALED_RECOVERY_INVALID`.
