# Repo Truth Index

Repo-truth files are authoritative project memory. They override chat memory, old handoffs, and ad hoc instructions unless explicitly updated by a later approved work package.

## Authority Hierarchy

1. `AGENTS.md` - Codex rulebook and protected operating rules.
2. `docs/project_charter.md` - project objective, scope, risk posture, and strategic direction.
3. `docs/project_status.md` - current phase, branch, merged WPs, and open decisions.
4. `docs/deferred_items_log.md` - deferred material issues, unavailable tools, blocked security checks, and postponed decisions.
5. `docs/source_repo_registry.md` - candidate external source repositories and audit status.
6. `docs/repo_reuse_strategy.md` - allowed external repo reuse paths and constraints.
7. `docs/repo_reuse_decision_matrix.md` - WP2 candidate repository reuse decisions.
8. `docs/architecture_principles.md` - platform architecture principles.
9. `docs/architecture_skeleton.md` - WP3 non-runtime architecture skeleton.
10. `docs/runtime_boundaries.md` - protected runtime boundary rules.
11. `docs/interface_contracts.md` - conceptual interface contracts for future implementation.
12. `docs/mode_separation.md` - historical, read-only, paper, and live mode separation.
13. `docs/security_tooling_requirements.md` - required future security and dependency-audit tooling gates.
14. `docs/data_semantics.md` - shared data definitions.
15. `docs/wallet_copy_trading_semantics.md` - wallet and copy-trading terminology.
16. `docs/risk_semantics.md` - risk definitions and initial posture.
17. `docs/live_trading_authorization.md` - live trading gate and authorization table.
18. `docs/security_and_secrets.md` - credential and incident rules.
19. `docs/codex_execution_guidelines.md` - work-package execution process.
20. `docs/work_package_template.md` - reusable WP template.
21. `docs/review_checklist.md` - review readiness checklist.
22. `docs/testing_requirements.md` - current and future test requirements.

Any material policy or architecture change must update the relevant repo-truth file in the same WP.
