# Repo Truth Index

Repo-truth files are authoritative project memory. They override chat memory, old handoffs, and ad hoc instructions unless explicitly updated by a later approved work package.

## Authority Hierarchy

1. `AGENTS.md` - Codex rulebook and protected operating rules.
2. `docs/project_charter.md` - project objective, scope, risk posture, and strategic direction.
3. `docs/project_status.md` - current phase, branch, merged WPs, and open decisions.
4. `docs/source_repo_registry.md` - candidate external source repositories and audit status.
5. `docs/repo_reuse_strategy.md` - allowed external repo reuse paths and constraints.
6. `docs/architecture_principles.md` - platform architecture principles.
7. `docs/data_semantics.md` - shared data definitions.
8. `docs/wallet_copy_trading_semantics.md` - wallet and copy-trading terminology.
9. `docs/risk_semantics.md` - risk definitions and initial posture.
10. `docs/live_trading_authorization.md` - live trading gate and authorization table.
11. `docs/security_and_secrets.md` - credential and incident rules.
12. `docs/codex_execution_guidelines.md` - work-package execution process.
13. `docs/work_package_template.md` - reusable WP template.
14. `docs/review_checklist.md` - review readiness checklist.
15. `docs/testing_requirements.md` - current and future test requirements.

Any material policy or architecture change must update the relevant repo-truth file in the same WP.
