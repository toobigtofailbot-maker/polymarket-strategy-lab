# Agent Context Export Schema

## Status

- Agent context export schema status: POLICY_SCHEMA_ONLY_NOT_IMPLEMENTED
- Agent context exporter status: NOT_STARTED
- Hermes runtime dependency status: NOT_INSTALLED_NOT_RUNTIME_DEPENDENCY
- Agent execution authority: FORBIDDEN
- Network access: FORBIDDEN_IN_SCHEMA_WP
- Account connection: FORBIDDEN
- Credentials: FORBIDDEN
- Fully autonomous trading agent: EXCLUDED_FOR_NOW

WP21 defines a future schema contract only. It does not implement a local exporter, agent runtime, Hermes setup, report generator, scheduler, network polling, account connection, credential path, strategy signal, trade proposal, backtest, paper trading, or live trading path.

## Purpose

This document defines the allowed shape of a future local read-only context package for advisory AI or Hermes consumption. The context package is intended to summarize repo-approved local evidence so a future advisory agent can observe, summarize, research, or propose items for human review.

The schema has no execution authority. Repo truth overrides exported context if they conflict, and stale exports cannot override current merged repo state.

## Required Top-Level Schema Sections

A future export must include these top-level fields:

- `schema_version`
- `export_created_at_utc`
- `export_mode`
- `producer`
- `source_commit`
- `repo_truth_summary`
- `included_local_artifacts`
- `data_quality_summary`
- `safety_boundaries`
- `deferred_items`
- `allowed_agent_uses`
- `forbidden_agent_uses`
- `redaction_policy`
- `staleness_policy`
- `human_review_requirements`

## Required Field Definitions

- `schema_version`: fixed semantic schema identifier for the exported context contract.
- `export_created_at_utc`: timestamp when a future exporter creates the context.
- `export_mode`: must be local, offline, and read-only.
- `producer`: future exporter name and version. WP21 does not create that exporter.
- `source_commit`: repository commit used to produce the export.
- `repo_truth_summary`: concise machine-readable status drawn from repo-truth docs.
- `included_local_artifacts`: list of local docs or reports included in the export. Each item must include path, type, provenance, optional checksum, and `generated_at` when available.
- `data_quality_summary`: quality status from offline local reports only.
- `safety_boundaries`: live trading, credentials, execution, scheduler, bot loop, Hermes runtime, and account connection statuses.
- `deferred_items`: relevant unresolved deferred items and why they matter to agent interpretation.
- `allowed_agent_uses`: observe, summarize, research, propose, and human-review handoff only.
- `forbidden_agent_uses`: direct orders, credentials, config mutation, scheduler activation, network scanning, private endpoints, signing, execution, and autonomous parameter application.
- `redaction_policy`: no secrets, account data, private keys, API keys, wallet keys, mnemonics, passphrases, tokens, authenticated headers, or raw private endpoint data are allowed.
- `staleness_policy`: exported context can become stale and cannot override repo truth, current merged state, current branch state, or later human review.
- `human_review_requirements`: any agent output affecting repo files, runtime behavior, configuration, polling, trading, deployment, or operations must go through human review and the normal Codex work-package flow.

## Mandatory Provenance Rules

- Every included artifact must be local artifacts only.
- Every included artifact must be repo-approved or generated by repo-approved local tools only.
- Every included artifact must include a source path and provenance classification.
- Generated artifacts must remain under ignored `local_data/` and must not be committed.
- Context export must not include raw private, account, credential, order, signing, or authenticated endpoint material.
- Context export must not include data obtained from private endpoints or account-specific queries.
- Context export must not read `.env` files or credential stores.

Allowed provenance classifications are:

- `repo_truth_doc`: tracked repo-truth document.
- `tracked_doc`: tracked project documentation that has no execution authority.
- `local_generated_report`: ignored local report generated by repo-approved offline tools.
- `local_snapshot_summary`: ignored local summary generated by repo-approved offline tools.

## Safety Contract

- The context export is not an agent runtime.
- The context export is not a signal generator.
- The context export is not a trade proposal.
- The context export is not a backtest.
- The context export is not paper trading.
- The context export is not live trading.
- The context export cannot authorize polling, scheduling, execution, account access, credentials, or Hermes network access.
- Agent outputs based on the context are advisory and untrusted until human review.
- Repo truth overrides exported context if they conflict.

## Allowed Inputs

Allowed inputs are limited to local, offline, repo-approved material:

- tracked repo-truth docs;
- tracked policy docs;
- tracked local schema docs;
- ignored local reports generated by repo-approved local tools;
- ignored local snapshot or quality summaries generated by repo-approved local tools.

Local generated inputs must stay under ignored `local_data/`. A future exporter may summarize those files only after a later approved WP implements and tests that exporter.

## Forbidden Inputs

The schema forbids:

- secrets;
- credentials;
- account connection data;
- private endpoints;
- private account queries;
- private trade queries;
- private order queries;
- order placement data;
- order cancellation data;
- signing material;
- API keys;
- private keys;
- wallet keys;
- mnemonics;
- passphrases;
- tokens;
- authenticated headers;
- `.env` contents;
- live, paper, or backtest decisions;
- autonomous parameter application records;
- scheduler, daemon, service, background worker, bot loop, or retry-loop state.

## Allowed Agent Uses

Future advisory agents may use a compliant export only to:

- observe local repo-approved context;
- summarize repo-truth status;
- research open questions using local evidence;
- propose human-review items;
- draft future Codex WP candidates for human review.

## Forbidden Agent Uses

Future advisory agents must not use a context export to:

- place orders;
- cancel orders;
- sign orders;
- submit orders;
- execute trades;
- read credentials;
- connect accounts;
- call private endpoints;
- perform network scanning;
- mutate configs;
- activate a scheduler;
- start a bot loop;
- run backtests;
- run paper trading;
- make live trading decisions;
- apply parameters autonomously;
- bypass human review or Codex work-package review.
