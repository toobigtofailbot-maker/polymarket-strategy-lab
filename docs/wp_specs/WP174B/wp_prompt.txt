FROZEN WALLET-READINESS DECISION (critical):

deployment is forbidden by this package. The Gate-B session MUST guarantee no deployment can occur:
it uses a non-deploying construction path plus an explicit deployment-status read and asserts the
selected Deposit Wallet is already deployed, failing closed (SDK_SIDE_EFFECT_UNAUTHORIZED) rather
than ever invoking the deploy branch. The dedicated canary Deposit Wallet, having been funded then
emptied, is already deployed, so the safe non-deploying path is operationally available.

6. REAL CANCEL, EMPTY-WALLET PROBE, AND VERIFICATION RECEIPT
===============================================================================

Cancellation is exposure-reducing and belongs to Gate B: cancel one known order, an explicit bounded
set of known order ids, cancel-market only with known ids/scope, or cancel-all for the exact
authenticated wallet. No cancel targets another wallet, accepts arbitrary raw request bodies,
bypasses identity, silently retries ambiguous mutation, or echoes raw venue errors. Every real cancel
attempt persists a safe attempt identity before transmit, performs at most one transmit for that
attempt, classifies the response, reconciles if ambiguous, and journals a sanitized result.

Required safe real mutation proof: one real cancel_all on a verified EMPTY dedicated Deposit Wallet.
Immediately before mutation the operator probe verifies expected signer/wallet exact, wallet_type
DEPOSIT_WALLET, collateral/pUSD available balance == 0, open orders == 0, positions == 0, no
unresolved local gateway mutation, healthy account reconciliation, and no other process owning the
wallet session. Any nonzero balance/position/open order returns GATE_B_ACCOUNT_NOT_EMPTY and the
probe does not run. The CLI requires an explicit operator confirmation phrase separate from the
key prompt. Expected result: the authenticated cancel endpoint is reached, zero orders are canceled,
no economic effect occurs, and a sanitized B4 receipt is produced. An ambiguous response closes only
through authoritative zero-open-order convergence; an unexpectedly canceled order is a protected
incident and STOP, never a hidden PASS.

Verification receipt: local generated evidence, never committed, short-lived (<= 60 minutes), and
content-addressed over sanitized public fields only (schema/receipt id, repository head, sdk
distribution/version, public signer/wallet, wallet/signature type, chain id, environment, credential
mode, read/empty/probe PASS flags, signing-probe id, cancel-probe attempt id and result, open-order
and position and balance snapshots before/after, verified/valid-until times, redaction pass). It
never contains a private key, API credential, signature bytes, signed order, authorization header,
or raw response, and never reactivates a secret session or grants live authority.
