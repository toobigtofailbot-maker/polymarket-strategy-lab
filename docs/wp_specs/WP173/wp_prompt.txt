1. OBJECTIVE
===============================================================================

Build the first persistent serious paper-trading system on top of merged WP172 executable-edge
evidence.

  validated WP172 paper-eligible assessment
  -> deterministic paper strategy/session binding
  -> deterministic paper intent
  -> hard pre-order paper-risk decision

  -> conservative fill processing using WP172-equivalent execution semantics
  -> cash / reservations / positions / fees / realized + unrealized PnL
  -> append-only audit evidence

  -> read-only operator cockpit projection

period against a caller-selected, locally available WP169 market-truth store that may be growing
while the existing WP169 public-data collector runs separately.

market truth read-only.

the entire OMS/accounting/risk/recovery path is testable without wall-clock or external network.

generator exists. Strategy-specific decision producers may submit validated paper intents through
the frozen paper-intent boundary; the replay adapter must be sufficient to prove the full engine
end-to-end from an approved WP172 decision trace.

6. SERIOUS PAPER DATA MODEL
===============================================================================

Implement immutable validated records with canonical serialization and exact Decimal-string
economics.

A. PaperStrategyBinding
- content-addressed ID;
- exact WP172 assessment ID;
- exact WP172 cost-model ID;
- experiment ID / first-look evidence ID;
- human-readable strategy instance label bounded/sanitized;
- created-at/event-time field;
- valid only when the supplied WP172 assessment validates, is EXECUTABLE_EDGE_PASS, and is
  wp173_evaluation_eligible;
- cannot broaden the assessed execution mode/cost assumptions.

B. PaperIntent
- content-addressed/idempotent ID;
- binding ID;
- market_id + asset_id;
- BUY or SELL;
- intended quantity;
- paper order style restricted to the cost model's assessed execution mode:
    AGGRESSIVE_TAKER or PASSIVE_MAKER;
- limit/reference price where required;
- created/decision receive-time;
- TTL for passive mode from frozen cost model;
- no account, wallet, key, venue credential, or real-order field;
- intent itself never bypasses risk.

C. PaperOrder
Closed lifecycle:
  PENDING_RISK
  REJECTED
  OPEN
  PARTIALLY_FILLED
  FILLED
  CANCELLED
  EXPIRED

Every transition is append-only evidence.
A rejected/cancelled/expired order cannot reopen.
Same intent ID + identical bytes is idempotent.
Same identity + different bytes fails closed.

D. PaperFill
- paper order ID;
- fill sequence;
- market/asset;
- side;
- quantity;
- price;
- fee;
- receive/event time;
- market-truth lineage/source reference;
- explicitly `SIMULATED_PAPER_FILL`;
- never contains/claims a venue order/trade ID.

E. PaperRiskLimits / PaperRiskDecision
At minimum freeze:
- initial paper cash;
- max single-order notional;
- max per-market gross exposure;
- max total gross exposure;
- max open orders;
- max session drawdown;
- max UTC-day loss;
- minimum free-cash reserve;
- max market-data age;
- optional max position quantity if it naturally fits the model.

Risk result is deterministic ALLOW or DENY with closed reason codes.
Every new order must have a persisted ALLOW decision before OPEN.
No AI/LLM/Hermes can modify or override limits.

7. ACCOUNTING / RESERVATIONS / PNL
===============================================================================

Implement a deterministic spot-token paper ledger.

Rules:
- paper cash starts from explicit caller-supplied initial cash;
- BUY may never make free cash negative;
- SELL may never exceed free owned quantity;
- no borrowing, shorting, leverage, margin, or synthetic negative inventory;
- open BUY orders reserve cash/notional/fees conservatively;
- open SELL orders reserve position quantity;
- reservations count toward exposure/risk so multiple open orders cannot oversubscribe resources;
- partial fill releases/adjusts reservations exactly;
- cancel/expiry releases remaining reservations exactly;
- fees use the frozen WP172 cost-model assumptions;
- weighted-average remaining cost basis includes applicable buy fees;
- realized PnL on reduction uses removed cost basis versus net sell proceeds;
- unrealized PnL uses the latest valid non-crossed two-sided market mid;
- equity = free cash + reserved cash + marked position value, with accounting identity tested;
- if current mark is unavailable/stale/gapped, mark-dependent PnL is explicitly unavailable rather
  than fabricated;
- all economic arithmetic uses Decimal/canonical strings, never binary float identity.

Resolution:
- when validated WP169 resolution truth unambiguously maps the held asset to winner/loser, cancel
  remaining open orders and settle paper inventory at deterministic 1/0 payoff;
- if resolution mapping is missing/ambiguous, freeze that market as RESOLUTION_PENDING, place no
  new paper orders there, and do not guess a payout.

===============================================================================
8. FILL MODEL — WP172 SEMANTIC EQUIVALENCE
===============================================================================

Do NOT use Nautilus default fills as paper truth.

Paper fills must preserve WP172 semantics incrementally:

Aggressive:
- decision -> latency -> arrival;
- use latest valid reconstructed book known by receive time at arrival;
- sweep actual visible depth;
- partial fill if insufficient depth;
- exact fee/slippage semantics consistent with the frozen cost model.

Passive:
- initialize queue-ahead from visible same-price size * frozen queue multiplier;
- price touch/book update alone never fills;
- only eligible opposite-aggressor trade flow after arrival consumes queue;
- fill only after queue ahead is consumed;
- expire at frozen TTL;
- adverse selection/markout reporting stays aligned with the WP172 cost model.

Required equivalence regression:
For a one-order replay with identical market events + cost model, final paper filled quantity,
average fill price, fee and relevant cost components must match the corresponding WP172
execution semantics exactly.

A narrow refactor/extraction of WP172 fill helpers is authorized only if it preserves WP172
public behavior byte/semantic-for-semantic and is covered by regression tests.
Do not redesign WP172.

9. PERSISTENCE / RESTART / RECONCILIATION
===============================================================================

Use a dedicated caller-selected local SQLite paper store.

Required:
- repo-owned application_id + user_version checked on every open;
- explicit path validation; no symlink tricks;
- append-only canonical event journal is the authoritative paper history;
- each journal event has monotonic sequence, stable event ID/type/time, canonical payload,
  previous-event hash and event hash;
- derived/materialized paper tables/snapshots may exist for efficient cockpit reads but are not
  allowed to contradict the journal;
- each logical mutation uses one SQLite transaction;
- duplicate identical mutations are idempotent;
- conflicting duplicate identities fail closed;
- no silent overwrite of historical events.

On startup/restart:
1. validate schema;
2. verify complete journal hash chain;
3. replay/recompute authoritative account/order/risk state;
4. compare against materialized snapshot/checkpoint;
5. if mismatch/corruption exists, enter RECONCILIATION_BLOCKED;
6. while blocked, no new order may open.

Crash/retry safety:
- a crash must not create duplicate orders/fills;
- no fill may exist without its paper order;
- no accounting mutation may occur without its journal evidence;
- restart after a committed fill must reconstruct exactly the same cash/position/PnL state.

10. PAPER RUNTIME / CONTROL MODEL
===============================================================================

Provide a manually launched foreground runtime only.

Required modes:

REPLAY
- caller supplies validated WP168/WP172 market-truth evidence plus paper intents / approved
  decision trace;
- deterministic finite execution;
- same input -> same journal/state IDs.

LIVE_STORE
- caller supplies a validated local WP169 SQLite market-truth path that may grow while the existing
  WP169 collector runs separately;
- WP173 opens it read-only and tails only new accepted canonical observations;
- no external market network client is created by WP173;
- polling cadence is bounded/configurable and does not change economic event ordering;
- stale/gap/reconciliation state blocks new paper order opening/fills as appropriate.

Paper controls:
  RUNNING
  PAUSED
  KILLED
  RECONCILIATION_BLOCKED

Rules:
- PAUSED prevents new orders but preserves state and existing evidence;
- KILLED is terminal for that paper session and cancels/expires remaining simulated open orders
  according to the frozen control rule;
- RECONCILIATION_BLOCKED cannot be manually overridden by an AI or strategy;
- resume is allowed only from PAUSED;
- no control path can change live-trading authorization because live does not exist here.

A thin local CLI/manual API for init/run/submit-intent/cancel/pause/resume/kill/status is allowed.
It must accept explicit local paths and validated structured input only.
No arbitrary command/plugin/dynamic-import surface.
