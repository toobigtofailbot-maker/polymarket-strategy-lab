0. PURPOSE
===============================================================================

This is the narrow upstream repair required by AF1 Attempt-03's consumed true stop.

Attempt-03 successfully completed its bounded public population and selected its benchmark
cases. The first blind Hermes case then failed before Hermes was launched:

_context_request(...)
→ build_research_run_request(...)
→ request secret scan
→ REQUEST_SECRET_DETECTED

The rejected value was a canonical PUBLIC Polymarket event identifier carried inside the
controlled request's `public_market_context`:

event:polymarket:0x<64 hex condition id>

Current merged HERMES-CTX contains this generic secret-like pattern:

    \b0x[a-fA-F0-9]{40,}\b

That rule is useful and MUST remain fail-closed for bare long-hex material, wallet/account
identifiers, private-key-like values and arbitrary request text.

The incompatibility is that the repository itself canonically represents public Polymarket
condition/event identity with a 0x-prefixed 64-hex value, and the controlled context path
serializes the canonical `subject_refs` into `public_market_context`.

This package therefore authorizes ONLY a field-aware compatibility exception:

- preserve the generic long-hex secret rule;
- preserve all existing secret/credential scanners;
- in `public_market_context` only, recognize narrowly defined canonical PUBLIC Polymarket
  identifiers as public identifiers rather than secrets;
- scan every remaining byte/string surface with the existing secret and authority rules;
- do not create a global long-hex allowlist;
- do not admit wallet/account identifiers merely because they are public blockchain values.

This package does NOT authorize another AF1 attempt.

2. PRE-DRAFT VERIFIED ROOT CAUSE
===============================================================================

The following facts are frozen as the compatibility basis.

A. Current shared secret scanner
--------------------------------

`src/research_runtime/hermes_controlled_runtime/models.py` contains a closed
`_SECRET_PATTERNS` tuple including:

- API-key phrases;
- secret-key phrases;
- password/private-key phrases;
- Bearer/Authorization material;
- `sk-...`;
- `ghp_...`;
- PEM private-key headers;
- access-token phrases;
- `\b0x[a-fA-F0-9]{40,}\b`.

`_scan_secret(text)` raises only the closed code:

REQUEST_SECRET_DETECTED

and does not echo the matched content.

B. Request-builder application
------------------------------

`build_research_run_request()` currently sends ordinary request strings through
`_require_str`, which invokes `_scan_secret` and `_scan_authority`.

`public_market_context` currently receives the same generic scan as ordinary prose.

C. Controlled-context construction
----------------------------------

`src/research_runtime/hermes_controlled_runtime/context_controller.py::_context_request`
builds a canonical JSON context containing:

- campaign_id
- scope_key
- exact_scope_json
- exact_scope_sha256
- information_cutoff
- subject_refs
- alpha_context_present = false

and passes that JSON string as `public_market_context`.

D. Canonical public Polymarket identifiers
------------------------------------------

Merged repository truth already defines public PIT identities including:

- `market:polymarket:<gamma id>`
- `event:polymarket:<condition id>` when a condition id exists
- `event:polymarket:market-<gamma id>` otherwise
- `token:polymarket:<raw token id>`

The public population contract states Gamma market id is the public market identifier and
CLOB token ids are public no-authentication identifiers.

The public population implementation constructs:

    event_id = "event:polymarket:" + condition_id

for a populated market with a condition id.

The Alpha discovery layer carries canonical market/event/token ids as
`canonical_market_subject_refs(...)`.

E. Existing repository precedent
---------------------------------

The execution-gateway sanitization layer already distinguishes public Polymarket condition/
market identifiers shaped as `0x` + 64 hex and long decimal token/asset ids from generic
secret-like material using field-aware logic.

Do NOT import or couple HERMES-CTX to execution-gateway code.
This is precedent for the semantic distinction only.

F. Attempt-03 evidence
----------------------

Provided local runtime evidence establishes that the real C1 campaign reproduced offline
with a fake backend and failed in the request builder before the Hermes backend was invoked.

The triggering public identifier had canonical form:

event:polymarket:0x<64 hex characters>

The AF1 synthetic Phase-A corpus had not carried that real identifier shape through this
scanner, so the incompatibility was not exposed before the consumed runtime attempt.

3. FROZEN REPAIR DESIGN
===============================================================================

The repair MUST be FIELD-AWARE and FAIL-CLOSED.

A. Do not weaken the global scanner
-----------------------------------

The existing generic long-hex pattern MUST remain in the global secret rules.

Do NOT:
- remove it;
- reduce its minimum length merely to make the test pass;
- exempt all 0x values;
- exempt all 64-hex values;
- exempt wallet addresses;
- add caller-supplied "safe digests";
- add a configurable public-id allowlist;
- normalize arbitrary strings into an accepted form.

All non-`public_market_context` request fields retain the existing generic secret scan.

B. Public-market-context-only admission
---------------------------------------

Introduce a private validation path used ONLY for the request field:

public_market_context

It must preserve the ordinary:
- string type validation;
- non-empty requirement;
- maximum length;
- authority-escalation scan;
- exact returned/original request bytes used for request identity.

It may treat ONLY exact canonical PUBLIC Polymarket identifiers as non-secret tokens for
secret-scanning purposes.

The minimum recognized canonical public forms are:

1. Gamma market id:
   `market:polymarket:<positive/non-empty decimal digits>`

2. Condition-backed event id:
   `event:polymarket:0x<exactly 64 hexadecimal characters>`

3. Gamma-fallback event id:
   `event:polymarket:market-<positive/non-empty decimal digits>`

4. CLOB token id:
   `token:polymarket:<positive/non-empty decimal digits>`

Use the repository's actual canonical case/shape contract where an existing validator
already makes it stricter. Do not invent a broader grammar.

The implementation may use private exact recognizers and a validation-only masking/removal
step before the existing `_scan_secret`, provided:

- the original `public_market_context` string is returned/stored unchanged;
- request identity is derived from the original exact string, not the masked copy;
- only exact complete canonical public identifier tokens are masked/ignored;
- malformed near-matches are not partially masked into safety;
- all remaining content still passes through the full existing `_scan_secret`;
- `_scan_authority` still evaluates the original public-market-context text.

C. No arbitrary namespaced bypass
---------------------------------

The following MUST NOT become a bypass:

- `event:other:0x<64 hex>`
- `foo:polymarket:0x<64 hex>`
- `event:polymarket:0x<40 hex>`
- `event:polymarket:0x<63 hex>`
- `event:polymarket:0x<65 hex>`
- `event:polymarket:0x<64 hex><extra token characters>`
- `event:polymarket:sk-...`
- `token:polymarket:sk-...`
- arbitrary caller text merely containing the word `polymarket`.

If a string looks like an attempted canonical Polymarket identifier but does not satisfy the
exact accepted grammar, it must NOT be stripped before generic secret scanning.

D. Wallet/account addresses stay outside the exception
------------------------------------------------------

A bare EVM-shaped address:

0x<40 hex>

must remain secret/sensitive-request material and fail with:

REQUEST_SECRET_DETECTED

A 64-hex bare value must also remain rejected.

A 64-hex value in any other request field remains rejected even if it happens to equal a
real public Polymarket condition id.

This repair is about canonical public market identifiers in the dedicated public-market
context, not about permitting arbitrary blockchain identifiers in Hermes requests.

E. Existing credential protection remains intact
-------------------------------------------------

At minimum these classes must remain rejected in `public_market_context` even when valid
public Polymarket ids are also present:

- API-key/secret-key markers;
- password/private-key markers;
- Bearer tokens;
- Authorization headers;
- `sk-...`;
- `ghp_...`;
- PEM private keys;
- access-token material.

The error remains a closed code and must not echo rejected text.

F. No schema / policy / authority churn
---------------------------------------

Do NOT bump solely for this correction:

- Hermes research request schema;
- Hermes receipt schema;
- ContextCampaignScope schema/version;
- Hermes invocation policy schema/version;
- controlled profile version;
- context reconciliation schemas.

Do NOT change:
- provider/model policy;

- toolset;

The Hermes invocation policy ID should remain unchanged unless implementation proves the
policy object itself necessarily changes. If it must change, STOP rather than introducing
