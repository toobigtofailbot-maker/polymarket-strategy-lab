9. MARKET STATE / FRESHNESS / DATA-GAP SEMANTICS
===============================================================================

Knowability and freshness use DIFFERENT clocks and MUST NOT be interchanged.

HISTORICAL VISIBILITY / KNOWABILITY CLOCK:
- shared PIT query cutoff_mode is AS_OF_INGESTION_TIME;
- ingestion_time controls whether a record is eligible to be historically visible at T0;
- ALPHA-02 does not override this with event_time, observed_time or source-declared time.

FRESHNESS CLOCK:
- freshness age uses authoritative record.envelope.observed_time;
- metadata freshness: authoritative MARKET_METADATA envelope.observed_time;
- order-book freshness: authoritative ORDER_BOOK envelope.observed_time, NOT payload.clob_timestamp;
- resolution-rule freshness: EACH authoritative ResolutionRuleSnapshotRecord envelope.observed_time,
  NOT source_declared_effective_time;
- referenced source-snapshot freshness: the exact PIT-visible SourceSnapshotRecord envelope.observed_time
  resolved through Section 8, never a direct store-only candidate;
- multiple rule/source entities remain individually visible; v1 does not choose a single preferred
  source by hierarchy rank.

Age calculation:
  age_seconds = as_of - observed_time

Closed freshness state:
- FRESH when 0 <= age_seconds <= the explicit policy threshold;
- STALE when age_seconds > threshold;
- INVALID_CLOCK when observed_time is malformed or observed_time > as_of;
- MISSING when the relevant authoritative record does not exist.

Boundary is therefore exact:
  age == threshold => FRESH
  age > threshold  => STALE

INVALID_CLOCK never becomes fresh and is treated as a data conflict for the affected dimension.

For each observed market derive deterministic state only from authoritative PIT evidence:
- market_id / event_id;
- market status;
- condition id;
- token set;
- outcome set;
- resolution date/category when present;
- metadata record/version id and observed/ingestion times;
- resolution-rule/source record ids when present;
- per-token order-book record ids when present;
- last trade / tick / minimum order size when present;
- metadata/rule/source/book freshness state;
- explicit DATA_MISSING / DATA_CONFLICT flags.

Required metadata subfields for allocation readiness:
- market_status;
- non-empty token_ids;
- non-empty outcome_labels.

Optional metadata gaps:
- condition_id;
- category;
- resolution_date.

Rules:
- required metadata missing/conflicted or metadata STALE/INVALID_CLOCK => DEFER_CAPTURE_REFRESH;
- optional metadata missing => READY_WITH_CAPTURE_GAPS, not globally ineligible;

10. MATERIAL CHANGE CONTRACT
===============================================================================

Compare an earlier and later AlphaUniverseSnapshot built under the SAME canonical comparison policy.
Require earlier.as_of < later.as_of.

A changed record_version_id alone NEVER proves semantic change.
Material change is computed only from the canonical source/field/formula table below.

EXACT FIELD-SOURCE / COMPARISON TABLE

| Change class | Canonical source | Normalized comparison | Missing-side behavior | Reopen-material? |
| --- | --- | --- | --- | --- |
| MARKET_STATUS_CHANGED | MARKET_METADATA canonical_payload.market_status | exact canonical string | not compared when market absent from either universe; required-field missing in present market = DATA_CONFLICT | YES, subject to current market eligibility |
| CONDITION_ID_CHANGED | MARKET_METADATA canonical_payload.condition_id | null/empty => null; otherwise stripped exact string | same as metadata above | YES |
| TOKEN_SET_CHANGED | MARKET_METADATA canonical_payload.token_ids | each raw id => token:polymarket:<raw>; sorted unique tuple; duplicate/invalid raw id => DATA_CONFLICT | same as metadata above | YES |
| OUTCOME_SET_CHANGED | MARKET_METADATA canonical_payload.outcome_labels | sorted unique exact canonical strings; duplicates => DATA_CONFLICT | same as metadata above | YES |
| RESOLUTION_RULE_CHANGED | sorted authoritative ResolutionRuleSnapshotRecord mapping keyed by resolution_source_id | for every resolution_source_id present on BOTH sides, compare exact validated rule_content_sha256; emit once when any shared source hash differs and retain affected source ids | zero rules on either side => DATA_MISSING; source additions/removals are handled by RESOLUTION_SOURCE_CHANGED rather than double-counted here | YES |
| RESOLUTION_SOURCE_CHANGED | sorted set of authoritative ResolutionRuleSnapshotRecord.resolution_source_id | exact sorted-set equality | zero rules on either side => DATA_MISSING; otherwise set addition/removal emits class with affected source ids | YES |
| TICK_SIZE_CHANGED | ORDER_BOOK canonical_payload.tick_size per shared token | Decimal numeric equality | missing/invalid book/value on either side => DATA_MISSING/DATA_CONFLICT for token, no class from that token | YES |
| MIN_ORDER_SIZE_CHANGED | ORDER_BOOK canonical_payload.minimum_order_size per shared token | Decimal numeric equality | same as tick size | YES |
| LAST_TRADE_PRICE_MOVED | ORDER_BOOK canonical_payload.last_trade_price per shared token | abs(after-before) >= policy.soft_last_trade_price_abs_delta | null/missing/invalid either side => DATA_MISSING/DATA_CONFLICT, no class from token | YES when threshold crossed |
| MID_PRICE_MOVED | ORDER_BOOK bids/asks per shared token | midpoint formula below; abs(after-before) >= policy.soft_mid_price_abs_delta | one-sided/missing/invalid book => DATA_MISSING/DATA_CONFLICT, no class from token | YES when threshold crossed |
| SPREAD_CHANGED | ORDER_BOOK bids/asks per shared token | spread formula below; abs(after-before) >= policy.soft_spread_abs_delta | one-sided/missing/invalid/negative spread => DATA_MISSING/DATA_CONFLICT, no class from token | YES when threshold crossed |
| TOP_DEPTH_CHANGED | ORDER_BOOK bids/asks per shared token | relative-depth formula below >= policy.soft_top_depth_relative_delta | one-sided/missing/invalid book => DATA_MISSING/DATA_CONFLICT, no class from token | YES when threshold crossed |
| QUESTION_TEXT_CHANGED | MARKET_METADATA canonical_payload.question_text | exact canonical string inequality | present-market missing value => REVIEW_ONLY data issue | NO — REVIEW_ONLY |
| CATEGORY_TEXT_CHANGED | MARKET_METADATA canonical_payload.category | exact canonical scalar; null is distinct from non-null | present-market missing/null change is REVIEW_ONLY | NO — REVIEW_ONLY |

ORDER-BOOK DECIMAL FORMULAS

For each shared token with comparable before/after books:
- parse every price/size/tick/min-order/last-trade numeric string with Decimal; binary float forbidden;
- bid price and ask price must be in [0,1]; size must be >= 0;
- best_bid = max(bid.price) when bids non-empty;
- best_ask = min(ask.price) when asks non-empty;
- if either side empty => one-sided/missing book for MID/SPREAD/TOP_DEPTH;
- if best_ask < best_bid => DATA_CONFLICT;
- midpoint = (best_bid + best_ask) / Decimal("2");
- spread = best_ask - best_bid;
- bid_top_depth = sum(size for bid levels whose price == best_bid);
- ask_top_depth = sum(size for ask levels whose price == best_ask);
- top_depth = bid_top_depth + ask_top_depth;
- top_depth_relative_delta:
    * if before_depth == 0 and after_depth == 0 => Decimal("0");
    * otherwise abs(after_depth-before_depth) / max(abs(before_depth), abs(after_depth));
- threshold comparison is >=, never >;
- no epsilon constant is permitted.

PER-TOKEN AGGREGATION
- TICK_SIZE_CHANGED, MIN_ORDER_SIZE_CHANGED and every SOFT class compare only tokens present in
  BOTH snapshots;
- TOKEN_SET_CHANGED separately captures token additions/removals;
- ANY shared token crossing a class threshold is sufficient to emit that class ONCE for the market;
- MaterialChangeEvent stores sorted affected_token_ids per per-token class;
- market-level averaging across token changes is forbidden.

EVENT SHAPE
Emit at most ONE MaterialChangeEvent per market/pair of universe snapshots. It stores:
- prior/current universe ids;
- market id;
- sorted hard classes;
- sorted soft classes;
- sorted review-only classes;
- affected-token mapping;
- exact before/after record ids used per class;
- explicit DATA_MISSING/DATA_CONFLICT comparison diagnostics;
- policy id;
- authority booleans.

Only HARD and threshold-crossing SOFT classes are reopen-material. REVIEW_ONLY classes cannot
trigger reopen.

NEWLY / NO-LONGER OBSERVED LOCAL MARKETS
- prior/current set-difference semantics exist ONLY when the caller supplies an exact prior
  AlphaUniverseSnapshot under the same comparison policy; its id becomes
  comparison_prior_universe_id.
- when no prior universe is supplied:
  * comparison_prior_universe_id = null;
  * newly_observed_locally = false for every current market;
  * prior_only_market_ids = empty;
  * no material-change comparison is attempted.
- current-only market under an explicit prior/current comparison =>
  newly_observed_locally=true; NO MaterialChangeEvent is created because there is no comparable
  prior state. The market is triaged normally; absent current Alpha match under current-memory
  posture it maps to NEW_RESEARCH.
- prior-only market under an explicit prior/current comparison => NO MaterialChangeEvent and NO
  current MarketTriageDecision. Its market id is retained in
  AlphaResearchQueueSnapshot.prior_only_market_ids with reason NO_LONGER_OBSERVED_LOCALLY.
  This does NOT assert that Polymarket closed/deleted the market and NEVER triggers reopen.
- every final triage/queue record carrying newly/prior-only comparison semantics binds the same
  non-null comparison_prior_universe_id.
- set difference alone is not evidence of a semantic market change because the observed universe
  is intentionally bounded/possibly incomplete.
