1. TRIGGER / OBJECTIVE
===============================================================================

Trigger: the real Phase-B run of the merged parent on the AlphaVPS C8G host stopped with
STOP BOOTSTRAP_ACTIVATION_DEFECT after the governed bootstrap reported BOOTSTRAP_COMPLETE:

- RELEASE_FILE_SET_MISMATCH: `pip install "$target_release"` built in-tree inside the immutable
  release, leaving build/ and src/polymarket_strategy_lab.egg-info, so verify-release
  --allow-activation-artifacts (and therefore execution-host-bind / currentness) failed;
- RUNTIME_VENV_NOT_EXECUTABLE: under umask 027 the root-created venv was 0550 root:root, so
  User=polymarket could not execute it (telemetry 203/EXEC; the critical probe would fail alike).

Objective: repair the governed Ubuntu bootstrap so that
1. package installation cannot contaminate the immutable release;
2. the polymarket runtime user can execute the installed venv (and never write it);
3. bootstrap fails closed before activation if either invariant is false.

Required successful order: verify pristine incoming release -> copy target release -> create venv
-> install from a disposable copy of the pristine release -> pip check -> chmod -R go+rX,go-w ->
runuser -u polymarket executes the venv python and resolves project metadata -> chmod -R a-w ->
post-install verify-release --allow-activation-artifacts -> systemd unit verification -> UFW gates
-> atomic current switch -> service activation. The disposable source is removed on PASS and via
the EXIT trap on every FAIL; first-deploy staged-current cleanup is unchanged.
