1. OBJECTIVE
===============================================================================

Reduce high-volume GitHub Actions usage without weakening final exact-head evidence.

Normal future execution becomes:

  local focused/adjacent checks while editing
  -> one local authoritative broad/full suite once candidate is stable
  -> keep PR DRAFT while implementation changes are being pushed
  -> mark PR Ready for review only after stable local validation
  -> one full hosted compatibility/audit matrix on that exact non-draft head
  -> Side review
  -> Karl merge

If the final source head changes after hosted CI, fresh exact-head hosted CI remains required.

Do not reduce final test coverage. Reduce hosted RUN FREQUENCY, not final matrix strength.

===============================================================================
2. CURRENT PROBLEM / CURRENT CI TRUTH
===============================================================================

Current .github/workflows/ci.yml:
- triggers on every pull_request activity;
- also runs again on push to main;
- has five top-level jobs producing nine hosted jobs through matrices;
- runs full compatibility/full-suite work even while a PR is still a draft and changing;
- therefore repeatedly spends hosted CI on intermediate heads;
- Windows hosted runners can also queue/cancel, making repeated matrix launches especially wasteful.

PR #219 demonstrated the cost: the exact final matrix eventually passed, but repeated Windows
runner allocation failures required job-specific reruns. The desired future behavior is to avoid
launching the expensive matrix on draft implementation pushes in the first place.

===============================================================================
3. FROZEN IMPLEMENTATION DESIGN
===============================================================================

Modify .github/workflows/ci.yml only in scheduling/governance semantics.

A. Pull-request trigger
Use pull_request events sufficient to cover:
- opened
- synchronize
- reopened
- ready_for_review

Do not use pull_request_target.

B. Draft suppression
Every current top-level CI job must have a job-level condition equivalent to:

  github.event.pull_request.draft == false

Result:
- a draft PR may be opened and pushed repeatedly with hosted jobs skipped;
- marking it Ready for review launches the full hosted matrix;
- a later commit pushed while non-draft launches fresh exact-head CI.

C. Remove duplicate post-merge full matrix
Remove the current push-to-main trigger.

This workflow's authoritative expensive evidence is the final non-draft PR head.
Do not launch the same full matrix again merely because that already-green PR merges to main.

D. Same-PR concurrency
Add workflow concurrency equivalent to:
  group: ci-pr-${{ github.event.pull_request.number }}
  cancel-in-progress: true

This prevents stale same-PR hosted runs from continuing if a newer eligible head appears.

E. Preserve final coverage
Do NOT:
- remove or rename any current top-level CI job;
- remove any OS/Python matrix member;
- remove dependency audits;
- remove cockpit frontend checks;
- remove NDFD GRIB checks;
- remove strict DuckDB behavior;
- remove focused tests;
- remove the full pytest step;
- weaken exact dependency assertions;
- add path filters that can skip parts of the final matrix;
- change dependency pins.

Expected final hosted job coverage remains nine jobs:
- compatibility: ubuntu py3.12 / py3.14 + windows py3.12 / py3.14
- dependency-audit ubuntu py3.12
- ndfd-grib-compat ubuntu/windows py3.12
- ndfd-grib-dependency-audit ubuntu py3.12
- cockpit-frontend node 24.18.0

4. FUTURE LOCAL-FIRST GOVERNANCE
===============================================================================

Update canonical workflow guidance so future WPs follow this default:

WHILE EDITING
- run focused/adjacent/static checks locally in Claude Code;
- batch same-scope corrections before pushing;
- do not use GitHub Actions as the iterative development test loop.

STABLE CANDIDATE
- run readiness --check-diff;
- run artifact/diff/security checks;
- run one authoritative broad/full suite locally;
- use the existing authorized ephemeral Linux Docker pattern when local native modules are blocked;
- run platform-specific local checks where technically practical.

PR PUBLICATION
- create/update one DRAFT PR;
- keep it draft while source is changing;
- only after local stable-candidate PASS, mark Ready once and obtain full exact-head hosted CI.

AFTER A REAL HOSTED TEST FAILURE
- convert back to draft before iterative repairs where practical;
- fix/batch locally;
- rerun local validation;
- mark ready again only when stable.

HOSTED INFRASTRUCTURE FAILURE ON UNCHANGED HEAD
- rerun only the affected cancelled/failed-to-start job where GitHub supports it;
- do not rerun already-green jobs;
- a cancellation before runner/test execution is infrastructure evidence, not a code PASS or FAIL.

EXACT-HEAD RULE
- any source/workflow change after hosted PASS invalidates that exact-head hosted evidence;
- fresh hosted CI is then mandatory.
