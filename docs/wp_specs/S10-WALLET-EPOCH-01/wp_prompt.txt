# 4. Normative correction — exactly one wire conversion

**R001. Preserve API/canonical shape:** Keep the existing public signatures, parameters, feed keys, client class, endpoint paths and host checks. Callers continue to supply canonical UTC ISO timestamps in `start`/`end`; `WalletIngestRequest`, `pre_run_preimage`, `ingest_run_key`, `FeedAcquisitionReceipt.requested_start/end`, replay/PIT clocks and source first-seen semantics **remain unchanged**. Do not teach the contract builder to accept epoch strings or alter canonical records.

**R002. Convert at the client boundary only:** Immediately before forming the `parameters` array for `/v2/trades` and `/v2/activity`, convert **both** verified UTC timestamps to non-negative decimal Unix epoch-second strings using deterministic, integer-safe standard-library arithmetic; never float/round/silently truncate and never use local timezone. Conversion applies identically on the first page and any cursor page. Preserve the existing `cursor` validation, query ordering, `taker_only=false`, `exclude_deposits_withdrawals=false`, `sort_direction=ASC`, `limit`, and `user` rules. Recorded source `request_parameters` must truthfully show the *epoch wire values*; requested scope in canonical receipt stays ISO UTC. There is no contradiction: they represent the same instants at different boundaries.

**R003. Fail before dispatch:** Validate `start` and `end` as ISO UTC with explicit `Z`, a real calendar date/time and complete HH:MM:SS; reject any offset, naive, empty, wrong-type, leap-second, out-of-range, or non-canonical value before the client's opener can be called. An optional fractional part is allowed **only if its fraction is entirely zero**, to avoid unrepresentable subsecond precision on an integer-seconds API; nonzero fractions must return the existing closed `FIELD_VALUE_INVALID`/`FIELD_TYPE_INVALID` category before network. Reject `start > end`. Whether equal endpoints are valid must follow the existing native wallet request contract; do not invent new source semantics; tests cover that decision from current repo truth. Use a small private helper in `public_client.py` or an already import-safe native canonicalization helper; do not create a new module or a duplicate time model. Invalid-input errors must not echo values.

**R004. Network safety unchanged:** Keep fixed `https://data-api.polymarket.com`, no auth, no cross-origin redirect, no retry, no automatic loop at the client level, byte cap, page limit, cursor cap, Decimal parse, endpoint identity, closed errors and existing guards. Preserve `combo` feed completely (no `start/end`). Do not make actual network requests during this WP.

**R005. Existing lifecycle must work offline:** Under a mocked/intercepted native opener, the existing `ingest_wallet_evidence(mode='NETWORK')` path must make the documented epoch-query wire request while finalizing an ISO-window receipt; replay of its output through `load_and_verify_wallet_evidence_ledger` must verify.
