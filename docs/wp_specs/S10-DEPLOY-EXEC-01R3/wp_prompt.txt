1. TRIGGER / OBJECTIVE
===============================================================================

Trigger (real Phase B, deployed b815eed release): bootstrap, binding, strict currentness, SIGKILL
restart and the isolated window passed (240 samples, p95 250.084 ms), then the one canonical public
smoke failed after about 1 s with RESPONSE_TOO_LARGE (raw 9, normalized 110, store_bytes 726660,
zero Polygon raw rows). Gamma/CLOB/Data HTTP and the WebSocket stored rows normally. The mixed
window was invalid and coexistence was EXECUTION_HOST_INCONCLUSIVE. Not a C8G capacity failure. The
R2 transport repair worked: the provider now answers; the next deterministic failure is the
certified 4 MiB response bound on the 100-block eth_getLogs range.

Defect (src/data_layer/polymarket/market_truth_onchain.py _collect_log_chunk): an eth_getLogs
response that _rpc_call rejects as RESPONSE_TOO_LARGE becomes a terminal failed receipt; there is
no subdivision of an oversized range.

Objective: preserve the certified 4 MiB Polygon RPC response cap and 100-block runtime lookback
while allowing an oversized multi-block eth_getLogs range to complete through deterministic
left-first bisection into smaller bounded ranges, with single-block oversize remaining terminal and
no provider, credential, trading, live, dependency or workflow authority change.

Required behavior:
- eth_getLogs [A, B] RESPONSE_TOO_LARGE with A < B -> mid = floor((A + B) / 2); collect [A, mid]
  completely, then [mid + 1, B]; recurse only when a child is itself RESPONSE_TOO_LARGE;
- A == B oversized -> terminal FAILED RESPONSE_TOO_LARGE; the same range is never re-requested;
- no random, time-dependent or estimated sizing; no probing outside the collection flow; no
  overlap and no skipped block;
- every child uses the same rpc closure (rate limiter and shared max_network_calls budget), store,
  latest_block, limits, parent received_at and shared seen_log_ids; raw cursors encode the actual
  child range; budget exhaustion keeps the existing STOPPED / NETWORK_CALL_LIMIT;
- every other error is terminal and never subdivided; no retry of an identical request; no provider
  fallback;
- unchanged: max_response_bytes 4,194,304; onchain_lookback_blocks 100; max_block_span 2,000;
  confirmation depth; chain id 137; drpc only; four-method allowlist; R2 headers and HTTPError /
  transport-error classification; checkpoint resume, pending-tail replay, reorg invalidation and
  healing, block hash/timestamp verification, append-only raw evidence, observation identity,
  PENDING/CONFIRMED finality, receipt/error vocabulary and public signatures;
- a child failure after earlier children succeeded keeps their append-only evidence and returns the
  truthful terminal failure; the chain checkpoint is written only after the whole requested range
  completes, as before.
