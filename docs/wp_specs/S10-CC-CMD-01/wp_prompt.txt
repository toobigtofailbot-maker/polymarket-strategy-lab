## 8. Canonical Conditional Append Contract

Do not change the public behavior of `append_strategy_lifecycle_record(...)`.

Add a narrow preview + conditional-append surface in `src/strategy_lifecycle/store.py`.

### 8.1 Preview

Input:
- existing lifecycle store path;
- exact candidate `LifecycleRecord`;
- exact expected current store head.

Result states are closed:

```text
PREVIEW_READY
IDEMPOTENT_REPLAY
STALE_HEAD
REJECTED
```

Rules:
1. fully validate path/record/store;
2. if exact record ID already exists with byte-identical canonical payload → `IDEMPOTENT_REPLAY` before head comparison;
3. same record ID with different payload → reject identity conflict;
4. otherwise loaded head must equal expected head;
5. apply candidate to copied replay state;
6. on `PREVIEW_READY`, return the verified pre-append snapshot/head plus candidate snapshot information without write; the command layer may inspect these snapshots only after duplicate/stale resolution.

### 8.2 Conditional append

Within `BEGIN IMMEDIATE`:

1. fully verify current store;
2. exact byte-identical existing record → `IDEMPOTENT_REPLAY` before stale-head check;
3. otherwise require current head == expected head;
4. apply candidate to copied state;
5. enforce existing record/store limits;
6. append one row and hash-chain entry;
7. reload/verify;
8. commit;
9. return committed record id + resulting head.

A stale expected head performs **zero write**.

The exact retry rule is the reason duplicate detection precedes expected-head rejection.

No migration/schema change.

## 13. Command Identity / Time

Frontend command request supplies safe integer `issued_at_ms = Date.now()`.

Backend:
- rejects bool/non-int/negative;
- requires time to fall inside the authenticated session validity window;
- permits at most 5 seconds positive clock skew;
- converts exactly to `created_time_ns = issued_at_ms * 1_000_000` with overflow check.

Canonical normalized command request + authenticated `operator_id` derives:

```text
command_digest = sha256(canonical compact JSON)
command_ref = cccmd:<operator_id>:sha256:<64hex>
```

No caller-provided idempotency key.

The exact same request reconstructs the exact same lifecycle record without consulting post-commit mutable state. Any state-derived value needed to build a canonical record is therefore carried explicitly in the normalized request.

For all five commands, after auth + exact request normalization:

