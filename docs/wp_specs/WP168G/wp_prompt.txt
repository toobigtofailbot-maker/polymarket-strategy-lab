Allowed ACTION tokens:

- ACCEPT
- REJECT
- NORMALIZE_LOWERCASE
- NORMALIZE_UPPERCASE
- PRESERVE_EXPLICIT_NULL
- PRESERVE_EXACT

Rules:
1. RULE_ID is unique `NR` + 3 digits.
2. DOMAIN, SUBJECT, CONDITION are explicit lowercase tokens.
3. SPEC_PATH is a valid `semantic_fields.items[].path` or NONE.
4. EVIDENCE_ID exists in `evidence_plan` or is NONE only for an explicitly accepted
   governance-only rule.
5. Semantic key = (DOMAIN, SUBJECT, CONDITION).
6. One semantic key may have only one ACTION/CANONICAL_EFFECT pair.
7. Same semantic key + incompatible action/effect => READINESS_SEMANTIC_CONTRADICTION.
8. Different DOMAIN values are intentionally distinct semantic keys.
9. Applicable negative-test rows must reference the governing NR id.
10. Applicable canonical-serialization/public-input sections must reference NR ids.
11. Missing DOMAIN is invalid when multiple input domains exist.

Mandatory WP168 regression:
- source_row.market + alternate ASCII hex case + NORMALIZE_LOWERCASE

=> PASS because domains differ.

Mandatory contradiction:
- source_row.market + alternate ASCII hex case + NORMALIZE_LOWERCASE
- source_row.market + alternate ASCII hex case + REJECT
=> FAIL with READINESS_SEMANTIC_CONTRADICTION.

7. EVIDENCE PLAN COHERENCE + POST-IMPLEMENTATION NODE/ADEQUACY VERIFICATION
===============================================================================

A pre-implementation gate cannot require brand-new tests to exist before the implementation
agent creates them. Therefore the readiness tool has two evidence phases.

PRE-IMPLEMENTATION PACKAGE-READINESS MODE (default):
For each pytest-backed `evidence_plan` item:
- parse exact `.py` test paths from the evidence command;
- require at least one exact test file target;
- search each existing target file for the exact named node;
- if the exact named node exists, classify it EXISTING_NODE;
- if the exact named node does NOT exist, classify it PLANNED_NEW_NODE when and only when the
  exact target test file is in `scope.required_changed_files` — this allowance applies whether
  the target file itself already exists on base or will be newly created by the WP;
- reject a missing node when its target test file is outside certified changed-file scope;
- reject ambiguous duplicate named nodes among existing targets;
- reject an empty/generic `expected_result` such as only "passes", "test exists", or "green";
- never treat a broad directory command alone as sufficient node targeting.

The planned-node decision is therefore keyed on NODE existence + certified target-file scope,
NOT on target-file existence. This is mandatory and is a regression requirement from the
independent V1 review.

POST-IMPLEMENTATION EXACT-HEAD MODE (`--check-diff --base ... --head ...`):
- every planned pytest node must now exist exactly;
- inspect each named test function with `ast`;
- recognize direct `assert`, `pytest.raises`, and evidence-bearing same-module helper calls;
- recursively follow same-module helpers to fixed maximum depth <=4;
- reject a named node with no reachable assertion/evidence primitive;
- do not claim this proves semantic correctness; it proves a minimum concrete assertion surface.

The readiness result may expose trusted counts and closed error codes only, never test source.

This split is mandatory. It prevents both failure modes:
- pretending future tests already exist before implementation; and
- reaching final review with evidence-plan names that were never actually implemented.
