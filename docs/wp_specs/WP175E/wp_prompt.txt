continuity_complete, advisory_only, and no_execution_authority. Identity binds
every semantic field except ID/safety booleans. No caller-provided boolean can
establish continuity.

WP169 store changes are additive read-only APIs only. APPLICATION_ID,
USER_VERSION, DDL, indexes, checkpoint identity, append semantics, and normal
open/verification authority remain unchanged. Queries are bounded,
deterministically ordered, exact-asset/interval scoped, include relevant earlier
gap state, cannot mutate rows/checkpoints, do not expose absolute paths, and fail
closed on malformed persisted evidence. No migration.

Continuity is true only when mechanically proven: exact one asset; first usable
observation is an ACCEPTED WS full book snapshot with book_ready=true; interval
is bounded, nonempty, and within one uninterrupted STREAMING epoch/session; no
CONNECTING, RECONNECT_WAIT, FAILED, second STREAMING, session boundary, open or
forbidden gap overlaps/begins in the interval; pre-interval gaps were healed
before the chosen snapshot; receive ordering is admissible; unsupported or
quarantined records are excluded. Forbidden gap reasons include DISCONNECT,
TIMESTAMP_REGRESSION, HASH_CONFLICT, PARSE_FAULT, QUEUE_OVERFLOW,
STORAGE_FAILURE, and REORG. A healed earlier gap followed by a later full
snapshot may begin a new epoch without rewriting gap history.

build_native_market_truth_window uses only accepted WS evidence, reconstructs
BOOK/TRADE from canonical WP169 payloads, starts from a full book snapshot,
preserves receive time as execution-knowledge time, uses Decimal/string exactness
without binary float, orders deterministically, binds exact observation IDs and
attestation into lineage, and never fabricates depth/trades or substitutes
CLOB/Gamma/Data/Polygon public API records for WS order-book truth.

assess_executable_edge accepts the exact MarketTruthWindow |
NativeMarketTruthWindow union. Validation/identity are type-specific, but
PASS/FAIL/INCONCLUSIVE/DIAGNOSTIC precedence and fee/fill/capacity/net-edge gates
remain unchanged. Native continuity grants no automatic PASS advantage.

run_wp172_replay accepts the same exact union. Only type compatibility changes;
PaperStrategyBinding, assessment binding, fills, accounting, risk,
reconciliation, and paper/live separation are unchanged. Existing PMXT replay
remains backward compatible.
