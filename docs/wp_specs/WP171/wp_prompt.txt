8. MINIMAL PRODUCT CONTRACT
===============================================================================

BACKEND ROUTES — EXACT MVP ROUTE SET

Domain routes:
- GET /api/health
- GET /api/overview
- GET /api/market-truth/recent
- GET /api/experiments
- GET /api/experiments/{experiment_id}
- GET /api/audit/recent

Do not add domain mutation routes.

LIST LIMIT SEMANTICS

For these list endpoints:
- optional query parameter: limit
- default: 50
- minimum: 1
- maximum: 100
- integer only
- invalid/out-of-range -> HTTP 400 with INVALID_INPUT
- no offset pagination in WP171
- no status filter in WP171
- no source filter in WP171
- no free-text search in WP171

This intentionally removes the previous unresolved pagination/status-filter design work.

ERROR RESPONSE — EXACT SAFE SHAPE

All cockpit-owned API errors use:

  {"error":{"code":"<TOKEN>"}}

Closed error tokens:
- INVALID_INPUT
- NOT_FOUND
- SOURCE_UNAVAILABLE
- INTERNAL_ERROR

HTTP mapping:
- INVALID_INPUT -> 400
- NOT_FOUND -> 404
- SOURCE_UNAVAILABLE -> 503
- INTERNAL_ERROR -> 500

Evaluation/precedence:
1. validate request syntax/limit/experiment-id shape;
2. open and validate required source store;
3. if a valid source is available but the requested experiment does not exist -> NOT_FOUND;
4. unexpected internal failure -> INTERNAL_ERROR.

Never return:
- exception strings;
- SQL;
- raw invalid caller values;
- local absolute paths;
- environment values;
- usernames;
- traceback text.

SUCCESS LIST SHAPE

List endpoints return:
  {"items":[...],"count":<returned_count>,"limit":<effective_limit>}

count is the number returned, never an unbounded total-count query requirement.

DETAIL SHAPE

Experiment detail returns:
  {"item":{...}}

HEALTH SHAPE

Health returns a compact object containing:
- status: OK or DEGRADED
- read_only: true
- wp169: configured/readable booleans
- wp170: configured/readable booleans

No local path values.

OVERVIEW SHAPE

Overview may use one compact stable JSON object with:
- market_truth summary;
- experiments summary;
- recent_activity summary;
- read_only: true.

The exact nested field names are frozen in wp_spec.json after inspecting actual available
WP169/WP170 fields. Do not require fields that predecessor stores do not contain.
