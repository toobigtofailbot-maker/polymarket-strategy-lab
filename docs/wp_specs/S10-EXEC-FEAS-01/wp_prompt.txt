Implementation semantics must be based on current official Polymarket documentation as checked on 2026-10-03.

Relevant frozen facts:

## 9.1 Market details

Gamma market state exposes current facts including:

```text
active

acceptingOrders
enableOrderBook
negRisk

```

Trading configuration includes:

```text
orderPriceMinTickSize
orderMinSize
feesEnabled
feeSchedule

```

`orderMinSize` is documented as minimum **USDC notional per order**.

Do not describe it as shares.

## 9.2 Order book

Public CLOB:

```text
GET https://clob.polymarket.com/book?token_id=<TOKEN_ID>
```

returns:

```text
market / condition id
asset_id / token id
timestamp
hash
bids
asks
min_order_size
tick_size
neg_risk
last_trade_price
```

The current official API presentation orders:

```text
bids ascending by price
asks descending by price
```

so the best bid and ask are the last entries in the raw arrays.

The package must normalize internally to:

```text
bids: descending price, best first
asks: ascending price, best first
```

before evaluation.

Never import WP172's ordering assumptions blindly.

## 9.3 Order types

Current relevant types:

```text
GTC
GTD
FOK
FAK
```

GTD:

- expiration is Unix seconds;
- must be at least three minutes in the future;
- venue applies a one-minute security threshold before stated expiration.

Post-only:

- applies to GTC/GTD resting orders;
- if it would immediately match, it is rejected.

## 9.4 Fees

Current official public market configuration contains:

```text
feesEnabled
feeSchedule.rate
feeSchedule.exponent
feeSchedule.takerOnly
feeSchedule.rebateRate
```

Official fee docs state makers pay no platform fee and takers pay on fee-enabled markets.

Current documented formula for exponent `1` is:

```text
fee_usdc = shares * fee_rate * price * (1 - price)
```

Official V2 SDK source also models the generalized platform fee rate as:

```text
fee_rate * (price * (1 - price)) ** fee_exponent
```

Use exact Decimal arithmetic.

Current fee documentation says venue fee amounts are rounded to five decimal places, but it does not freeze a rounding mode for this WP.

Therefore this package must **not claim an exact server-rounded fee**.

See Section 24.

A current public hard fact makes the exact intent mechanically incompatible.

## Implementation Notes (within the frozen contract)

- Division-derived values (fill_ratio, weighted_execution_price) are quantized to 18 decimal
  places in the conservative direction (ratio down, BUY VWAP up, SELL VWAP down); all other
  arithmetic is exact Decimal with inexact operations trapped.

  missing source is UNKNOWN (no source silently wins; Gamma notional units are never inferred from

- A malformed Gamma feeSchedule leaves fee facts null with FEE_CONFIG_UNKNOWN; an oversize body or
  a book too large for the bounded record is an INVALID source.
