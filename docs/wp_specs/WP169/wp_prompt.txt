===============================================================================
OBJECTIVE AND ARCHITECTURE
===============================================================================
Deliver one native public market-truth plane under src/data_layer/polymarket. It must:

1. Preserve exact raw bytes plus receive time and source metadata before normalization.
2. Normalize supported Market WebSocket events deterministically without floats.
3. Maintain per-asset book readiness, mark disconnect/regression/hash conflicts as gaps,
   and heal a gap only with a subsequent full book snapshot.
4. Persist append-only raw envelopes, normalized observations, sessions, gaps, and
   checkpoints transactionally in bounded local SQLite storage.
5. Support resilient public GET acquisition with allowlisted endpoints, bounded pagination,
   closed Retry-After handling, timeout, response-size, page, record, and retry limits.
6. Capture point-in-time dynamic configuration and raw Gamma resolution/lifecycle material;
   missing dynamic parameters remain explicit null/unknown, never fabricated defaults.
7. Ingest and decode public V2 OrderFilled logs from both official exchange addresses,
   retain confirmation state and block hashes, and invalidate affected checkpoints on
   detected reorgs. Unknown/malformed logs remain raw/quarantined.
8. Convert eligible accepted observations to the existing canonical PIT record builder;
   book, trade, and market metadata integrate with existing analytical materialization only
   through the existing PIT boundary. Acquisition SQLite itself has no canonical promotion
   authority. WP168 Nautilus replay accepts only its frozen WP167 pmxt-v2 external dataset;
   no direct PIT-to-Nautilus adapter is claimed or added by WP169. The preserved raw/event
   semantics make a later separately reviewed adapter possible without fabricating history.
9. Provide an explicit manual foreground CLI/runtime with graceful stop and bounded
   backoff. No import-time network, thread, process, scheduler, or file side effect.

Public output is closed and sanitized: stable status/error codes, counts, hashes, logical
source identifiers, event timestamps, and public market values only. Exceptions, URLs,
headers, environment values, local absolute paths, raw invalid inputs, or response bodies
must not be echoed by result/error surfaces.

Content identity and occurrence identity are intentionally separate. raw_sha256 is SHA-256
over the exact raw bytes. raw_id is markettruth:raw:sha256:<digest> over canonical JSON with
exact keys version="wp169-raw/1.0.0", source_kind, source_id, media_type, raw_sha256, and
byte_length; it excludes receive time. occurrence_id is
markettruth:occurrence:sha256:<digest> over the exact canonical JSON keys
version="wp169-occurrence/1.0.0", raw_id, received_at, source_id, source_cursor, and
occurrence_sequence. observation_id is markettruth:observation:sha256:<digest> over the exact
canonical JSON keys version="wp169-normalizer/1.0.0", source_content_id, source_kind, event_kind,
event_id, market_id, asset_id, event_time, canonical_payload_sha256, status, error_codes, book_ready,
and provenance_json. Each preimage is the canonical JSON object with the named full keys,
serialized by canonical_json_bytes; SHA-256 is lowercase hex and prefixes are literal.
source_content_id is raw_id for WS/HTTP observations. For POLYGON order_filled it is the
stable source_log_id defined below, so response batching and overlap do not alter event
identity; the observation still carries its actual raw_id and occurrence_id to bind the
containing response.
All event/receive times exposed by normalized records are UTC RFC3339 with exactly six
fractional digits and Z. WebSocket epoch-millisecond and Data API epoch-second values are
converted with integer arithmetic; no local timezone or float conversion is allowed.

Receive time is the primary knowability/order time but is excluded from content identity.
Venue event time is retained separately. Equal receive times order by source rank then event
rank then child_index from provenance, raw digest, canonical bytes, occurrence_id, and finally
the append-assigned archive sequence. Frozen source ranks are WS=10, CLOB=20, GAMMA=30,
DATA=40, POLYGON=50. Frozen event ranks are book=10, price_change=20,
last_trade_price=30, tick_size_change=40, best_bid_ask=50, new_market=60,
market_resolved=70, trade=80, activity=90, position=100, holders=110,
dynamic_config=120, order_filled=130, unsupported=900. No path, database row id, process id,
retry delay, or environment value belongs to content identity. Byte-identical duplicates
retain multiplicity as distinct occurrence rows while sharing content identity.
Stable source_id values are polymarket:market-ws, polymarket:data-api:<endpoint-token>,
polymarket:gamma:<endpoint-token>, polymarket:clob:<endpoint-token>, and
polygon:137:drpc:<rpc-method>. Endpoint tokens are exactly trades, activity, positions,
holders, markets, market-by-id, book, fee-rate, and clob-market-info. source_cursor is
ws:<session-id>:frame:<sequence>, http:<endpoint-token>:offset:<offset>:attempt:<attempt>, or
rpc:<method>:blocks:<from>-<to>:attempt:<attempt>. Session ids are lowercase UUID4 values;
sequences, offsets, attempts, and blocks are canonical base-10 nonnegative integers without
padding.

HTTP resume identity is endpoint plus canonical query plus next offset. Canonical query is
the canonical_json_bytes object of all validated endpoint parameters after every value is
normalized to its specified string form; key sorting is therefore byte-exact. The HTTP
checkpoint_key is "http:"+endpoint-token+":query:sha256:"+the lowercase SHA-256 of those
canonical query bytes after omitting offset only; next_offset lives in value_json. The WS
checkpoint_key is "ws:market:assets:sha256:"+the lowercase SHA-256 of canonical_json_bytes
over the ordered asset-id array. The chain checkpoint_key is exactly
"chain:137:order-filled-v2". /trades allows limit
1..10000 and offset 0..10000, /activity requires public user, limit 1..500, offset 0..5000,
/positions requires public user, limit 1..500, offset 0..10000, and /holders requires market
with limit 1..20 and no offset. Gamma/CLOB snapshot
requests are single page. WebSocket resume always reconnects/resubscribes and waits for a
book snapshot per asset; it never invents a sequence replay. On-chain resume is inclusive
from min(last_verified_block+1,oldest_pending_block), or the caller start when no checkpoint
exists, and deduplicates by the stable source-log identity below. PIT promotion is idempotent
only for the same logical occurrence (same raw bytes,
received_at, and caller snapshot/batch inputs) by the existing record_version_id. A
byte-identical observation received at a later time is intentionally a new source snapshot
and market-observation version because knowability changed; it is not silently deduplicated.

collect_public_page accepts offset=0 or an omitted offset for paged Data endpoints; direct
get_page remains available for any validated offset. With no ACTIVE same-query checkpoint a
crawl starts at zero. After each durably committed full page, it writes ACTIVE next_offset as
offset+limit; reaching max_pages with another valid offset leaves that checkpoint for the
next invocation. The next invocation resumes exactly there, not zero. An empty/short page or
the endpoint maximum offset writes SUPERSEDED with next_offset=0; the invocation ends and the
following cadence begins a new head crawl at zero. A failed page does not advance or reset
the prior checkpoint. Gamma/CLOB single-page requests never create offset checkpoints. This
bounded offset traversal can observe duplicates or upstream movement and preserves them as
occurrences; it does not claim snapshot isolation or gap-free historical backfill.

PIT eligibility is exact. ACCEPTED new_market, market_resolved, or Gamma market observations
are MARKET_METADATA only when event_id, market_id, question_text, market_status, and nonempty
outcome_labels are present. For new_market, event_id is the positive canonical base-10
event_message.id; top-level id is the Gamma market id and is not an event id. market_resolved
has no event id and therefore requires exact market_context. For Gamma market, event_id is
set only when events is an array containing exactly one object with a positive canonical
base-10 id; zero or multiple parent events leave event_id null. Market status is RESOLVED
when event_kind is market_resolved, or Gamma umaResolutionStatus is case-insensitively
"resolved", or Gamma automaticallyResolved is true; otherwise CLOSED when closed is true;
otherwise ACTIVE only when active and acceptingOrders are both true; otherwise INACTIVE.
Book/trade/market_resolved market_context, when needed, must be an ACCEPTED metadata
observation whose token list contains the candidate asset_id when one exists and whose
market_id matches. It may supply only a missing event_id. If both records have event_id they
must be equal; a context received after the candidate is not-as-of and rejects. ACCEPTED book
is ORDER_BOOK only when configuration is an ACCEPTED dynamic_config for the same asset, its
received_at is not later than the book received_at, and its payload contains nonnull exact
decimal tick_size and minimum_order_size; those two values are joined into the PIT book
payload with bids/asks. ACCEPTED last_trade_price, Data trade, or activity of type TRADE is
PUBLIC_TRADE only when event/market/token identity (direct or from the exact context), price,
size, canonical observed side, and nonempty public transaction reference exist. order_filled

HTTP responses retry only 429, 502, 503, and 504, at most max_retries after the first
attempt. Retry-After must be an ASCII integer seconds value 0..retry_after_max_seconds;
otherwise RETRY_AFTER_INVALID is recorded and deterministic exponential seconds 1,2,4...
capped at max_backoff_seconds apply. Other 4xx and invalid payloads do not retry. Every
response is byte-bounded before JSON parse. A page returning more than its endpoint maximum
or any record exceeding max_record_bytes fails the page closed without partial promotion.
get_page returns PublicPageResult.attempts containing one RawEnvelope per actual response,
including intermediate retryable error bodies, in attempt order; successful_attempt_index is
the zero-based final-success index or null. collect_public_page archives every attempt raw
before parsing and normalizing only attempts[successful_attempt_index].raw_bytes internally.
It never copies response JSON onto a diagnostic result. A transport failure before bytes exist creates no
fake raw envelope and returns the closed transport error. Every acquired raw response is
stored once before per-record normalization. Store row/content
byte or queue exhaustion is terminal and visible; nothing is silently dropped.
Self-imposed request caps are intentionally below verified provider limits: DATA, GAMMA, and
CLOB use their AcquisitionLimits calls-per-10-second caps; POLYGON uses its per-second cap.
A monotonic in-process token bucket delays within the current foreground run and never
exceeds max_network_calls. Gamma/CLOB metadata/config are collected immediately then every
60 seconds, selected Data pages immediately then every 10 seconds, and Polygon latest-block,
log, and finality checks immediately then every 12 seconds. No cadence is installed outside
the process. duration_seconds must be 1..max_runtime_seconds. On network-call,
reconnect-attempt, queue, store, or duration exhaustion the runtime checkpoints and returns a
receipt with the exact status/error/stop_reason mapping above; it does not silently continue.

Runtime orchestration is exact. Discovery requests Gamma /markets with limit=100, offsets
0,100,... up to config.max_pages, active=true, and closed=false. In upstream page/record order
it chooses the first record with active=true, closed=false, acceptingOrders=true, a canonical
conditionId, and clobTokenIds decoding either from the documented JSON-array string or an
already-decoded array to 1..100 valid unique token ids. Its token order is preserved, its
conditionId becomes runtime market context, and no later candidate is considered. Exhausting
the bounded discovery pages without one candidate returns FAILED/RESPONSE_INVALID/NONE.
Discovery raw attempts and the selected record are archived through collect_public_page.

For every selected asset, each CLOB cadence fetches /book and /fee-rate and the Market
WebSocket remains subscribed. When a runtime condition is known (explicit or discovered),
each CLOB cadence also fetches /clob-markets/{condition_id} and each Data cadence fetches
/trades with market=<condition>. It also fetches /holders with market=<condition>. When a
wallet is supplied, each Data cadence fetches /trades, /activity, and /positions with that
user; if a condition is also known, the same market filter is included in all three and the
single /trades call is shared rather than duplicated. Each paged Data surface uses limit at
its endpoint maximum, its checkpointed offset semantics below, and at most config.max_pages.
Gamma is otherwise
used only for active discovery. With explicit assets and no condition/wallet, no Data or
Gamma call is fabricated; the runtime uses only WebSocket, per-asset CLOB, and on-chain.

Every runtime invocation performs eth_chainId and requires exact 0x89, then eth_blockNumber
for the confirmation reference. If explicit from_block/to_block are present, their inclusive
range is collected. Otherwise the inclusive range is max(0,latest-onchain_lookback_blocks+1)
through latest. Collection uses only the frozen V2 addresses/topic and exact range bound.
At each later RPC cadence the latest block/finality checkpoint is refreshed and the next
inclusive unverified range is collected; no already verified range is fabricated or skipped.
The foreground runtime starts the WebSocket and periodic HTTPS/RPC loops in one asyncio
TaskGroup, shares the stop event and network-call budget, converts synchronous transports via
asyncio.to_thread, records first terminal outcome, signals sibling stop, waits for all tasks,
writes STOPPED checkpoints, closes the store, and returns one deterministically aggregated
receipt. Terminal error selection uses the single closed global error precedence above;
stop_reason is then selected from the exact terminal mapping for that winning error. Caller
stop, duration, and network-call limit apply only when no higher-precedence error exists.
Counts are sums over committed unique archive rows and the largest global checkpoint history
sequence is reported.
MarketTruthStore.append first revalidates byte length/hash/raw_id/occurrence_id/source domains
and commits the raw occurrence alone. It then revalidates every child's raw_id, occurrence_id,
received_at, payload hash/size, canonical JSON, provenance schema, status/error consistency,
and recomputed observation_id before one all-or-nothing child transaction. One invalid child
commits no children and returns STORE_CONFLICT, while the already committed exact raw evidence
remains. Re-appending an identical occurrence id/raw row is idempotent; different content at
an existing occurrence id is STORE_CONFLICT. Within one HTTP/RPC response, records normalize
in upstream array order and all successful/quarantined normalized children commit together.
A page-level bound or JSON-shape failure commits only the raw envelope plus one valid
quarantined observation; it never partially promotes records. Within a WebSocket
price_change frame, output order is the exact price_changes array order and all child
observations commit atomically after raw. Within eth_getLogs, accepted logs sort by numeric blockNumber, transactionIndex,
logIndex, then lowercase address; exact source-log duplicates share observation identity and
are not re-promoted, but each response occurrence remains archived. HTTP resume checkpoints
advance only after the whole page transaction commits; WebSocket readiness changes only after
the whole frame transaction commits; chain checkpoints advance only after the whole block
range commits.

WebSocket initial payload is exactly {"assets_ids":[...],"type":"market",
"custom_feature_enabled":true}; dynamic messages use operation subscribe/unsubscribe and
assets_ids. SubscriptionUpdate.operation is exactly subscribe or unsubscribe; its asset set
obeys the same bounds. While STREAMING the runner races recv, heartbeat, stop_event, and the
controller's owned bounded queue and overflow flag. submit uses put_nowait; QueueFull sets a
sticky overflow flag and returns REJECTED/QUEUE_LIMIT_EXCEEDED, so the runner always observes
producer overflow on its next wait cycle. A subscribe sends the exact update then adds new assets
as NOT_READY; unsubscribe sends then removes only existing assets. Invalid/duplicate/no-op
updates are rejected INPUT_INVALID without a wire send; queue overflow makes all assets
GAPPED and terminates with the exact queue outcome below. The runner sends text PING each
heartbeat_seconds and accepts text PONG. Backoff
is deterministic 1,2,4,8,16,30 seconds and resets after an accepted full book snapshot.
Session transitions are IDLE->CONNECTING; CONNECTING->STREAMING or RECONNECT_WAIT or FAILED;
STREAMING->RECONNECT_WAIT on disconnect/continuity/queue fault, ->STOPPED on caller stop,
or ->FAILED on storage/config exhaustion; RECONNECT_WAIT->CONNECTING or STOPPED.
MarketBookState.plan is pure and computes all per-asset transitions against one immutable
state snapshot. The runtime archives raw first and then every planned observation in the
separate all-or-nothing child transaction, then calls commit exactly once after both succeed. If child storage
fails it calls discard, which changes every affected in-memory asset to GAPPED with
STORAGE_FAILURE and returns one GAPPED BookApplyResult per asset; no READY state is advanced
by a partial frame. The raw occurrence remains authoritative evidence even when gap-event
persistence is unavailable.
Per-asset book transitions are NOT_READY->READY on accepted book; READY->GAPPED on disconnect,
timestamp regression, same-timestamp hash conflict, invalid delta, parse fault for that asset, or queue overflow;
GAPPED->READY only on a subsequently archived and accepted full book. Deltas during NOT_READY
or GAPPED are archived with BOOK_GAP_ACTIVE and applied=false.

Reconstruction is deterministic and decimal-only. Each asset state is market_id,
last_timestamp_ms, last_hash, and price->size maps for bids/asks. A full book replaces both
maps after validating exact canonical decimals, price in [0,1], size >0, unique numeric price
per side, and best bid < best ask when both exist. A price_change BUY updates bids and SELL
updates asks: size >0 upserts the numeric price; size 0 deletes an existing level; deleting a
missing level, negative/noncanonical values, crossed book, provided best_bid/best_ask not
equal to the reconstructed extrema, timestamp regression, or the same timestamp with a
different nonnull hash is EVENT_INVALID plus CONTINUITY_GAP and makes that asset GAPPED.
Decimals allow at most 18 fractional digits and canonicalize without exponent, redundant
leading/trailing zeros, or negative zero; state sizes are capped at 10^30. Bids serialize
descending, asks ascending, each as [price,size]. state_json is exact
{"assets":{"<asset_id>":{"state":...,"market_id":...,"last_timestamp_ms":...,
"last_hash":...,"last_observation_id":...,"bids":[...],"asks":[...]}}}, with asset keys
in numeric order. last_observation_id is null before the first applied observation and is the
full markettruth:observation:sha256 id afterward.

snapshot_json returns that state. The ws checkpoint embeds the same book_states object.
MarketTruthStore.load_checkpoint verifies the complete same-key history chain before return;
from_checkpoint recomputes the returned checkpoint value hash, validates every state invariant, and
restores levels; the next actual connection calls mark_disconnect so restored assets are
GAPPED until new full snapshots. Tests apply a snapshot plus valid updates/deletes and compare
the resulting level sets to a separately received equivalent full snapshot, including restart
round-trip; equality covers all level bytes while timestamp/hash remain source evidence.
Official noncanonical-but-exact decimal spellings such as "0.50" are accepted, preserved in
raw evidence, and normalized to numeric canonical "0.5" before identity/state use. Each side
is capped at max_book_levels_per_side after every snapshot/delta; exceeding it gaps the asset
with QUEUE_LIMIT_EXCEEDED. An observation whose observation_id equals the asset's immediately
prior observation is an exact duplicate: it archives as another occurrence and returns
NO_CHANGE before delete/upsert validation. A later redundant upsert of the same size is
NO_CHANGE but advances valid timestamp/hash; a non-consecutive delete of an absent level is
invalid and gaps. last_observation_id is included in the checkpointed asset state.

On-chain block ranges are inclusive, nonnegative, ordered, and at most max_block_span. A log
is PENDING until latest_block-log_block+1 >= confirmation_depth, then a later collection
appends CONFIRMED. chain_finality_events is append-only and keyed for state transitions by
(source_log_id,block_hash,finality_state); normalized_occurrences still retains every raw
response occurrence. The same source_log_id with identical decoded payload/finality has the
same observation_id across overlapping or differently batched RPC responses and is not
re-promoted; PENDING->CONFIRMED intentionally creates a new observation version bound to the
same source_log_id.

The chain checkpoint's last_verified_block is the greatest collected block whose depth is at
least confirmation_depth, never merely the end of a range containing PENDING logs. Its hash
is obtained even when that block contains no returned log. Each cadence first re-fetches
eth_getBlockByNumber for the checkpoint block and every distinct block holding a retained
PENDING log, then compares stored hashes. It next collects inclusively from the minimum of
last_verified_block+1 and the oldest pending block through the requested/latest block,
partitioned into max_block_span calls. Thus the entire unconfirmed tail is revisited until it
becomes confirmed. A mismatch at block N appends REORG_INVALIDATED, opens a chain gap, writes
a REORG_INVALIDATED checkpoint for the greatest prior hash-verified confirmed block, using
null last_verified_block/hash when none exists, and recollects N through latest; prior rows
remain. The recollection response is new raw evidence and any replacement log receives its
hash-bound source_log_id. Checkpoint history states are ACTIVE, STOPPED, REORG_INVALIDATED,
and SUPERSEDED. checkpoint_current is never an authority source without its history hash chain.
collect_order_filled_logs calls eth_getBlockByNumber once per distinct returned block, checks
the returned block number/hash against every log, parses its hex timestamp as nonnegative epoch
seconds, passes it as block_timestamp, and uses the resulting six-fraction UTC value as
NormalizedObservation.event_time. Missing/mismatched block data is RESPONSE_INVALID and none
of that range's normalized children or checkpoint advance.

Worked example truth:
- A raw Market WS book object for asset "7" with integer timestamp "1720000000000",
  bids [{"price":"0.40","size":"12"}], asks [{"price":"0.60","size":"8"}], and
  received_at "2024-07-03T09:46:40.000000Z" archives one RawEnvelope, normalizes one book
  observation with event_time "2024-07-03T09:46:40.000000Z", retains decimal strings, and
  moves asset 7 from NOT_READY to READY only after the append transaction commits.
- If a disconnect follows, a price_change for asset 7 is still archived but yields status
  QUARANTINED, error BOOK_GAP_ACTIVE, applied false. A later archived valid full book heals
  the open gap; no missing delta is fabricated.
- A Data API /activity record of type SPLIT is archived and normalized as activity but has
  no supported PIT observation kind, so build_point_in_time_observation returns a sanitized
  PIT_PROMOTION_FORBIDDEN result. A TRADE with condition/token identity can build PUBLIC_TRADE.
- A V2 OrderFilled log from either exact official exchange address with the exact topic and
  seven 32-byte ABI data words normalizes only when chain id 137, canonical block/tx/log
  identity, and confirmation state are known. A wrong topic yields LOG_TOPIC_MISMATCH while
  exact raw log response bytes remain in the trusted archive.
