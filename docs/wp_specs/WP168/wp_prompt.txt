DETERMINISM / IDENTITY, RECEIVE-TIME REPLAY ORDERING & CANONICAL SERIALIZATION (FROZEN)
===============================================================================
FROZEN EVENT_KIND_RANK (deterministic tie-break only; NOT a venue-causality claim;
changing it changes the conversion-policy identity/version):
  book = 0 ; price_change = 1 ; last_trade_price = 2 ; tick_size_change = 3.
This mapping is fixed here and in the spec; it must never derive from alphabetical,
enum-declaration, or any runtime-dependent ordering.

CANONICAL SEMANTIC SOURCE ORDERING (frozen — total, receive-time-primary,
physical-order-independent). WP168 is a point-in-time/knowability research foundation, so
the deterministic replay ARRIVAL order is defined by receive/init time first:
A. For every validated pmxt v2 source row, derive canonical semantic row bytes from the
   validated row content using the deterministic normalization contract below.
B. Derive a stable canonical_row_digest (SHA-256) from those canonical bytes.
C. Construct the canonical source multiset INDEPENDENTLY of filesystem enumeration order,
   Parquet file enumeration order, Parquet physical row position, DuckDB/Polars/query
   return order, Python stable-sort input order, and temporary/output paths.
D. Group rows whose canonical semantic bytes are exactly identical.
E. Sort the distinct canonical row groups by the frozen total key
   (ts_init, ts_event, event_kind_rank, canonical_row_digest, canonical_row_bytes), where
   ts_init = timestamp_received mapped to exact integer nanoseconds and ts_event =
   the venue/source timestamp mapped to exact integer nanoseconds; canonical_row_bytes is
   the final collision-safe semantic tie-break (not the digest alone).
F. For an exactly byte-identical duplicate group with multiplicity N, deterministically
   expand it with duplicate ordinal 0,1,...,N-1 derived from multiplicity in the canonical
   multiset (NOT from physical/source order). Identical rows are NEVER silently
   deduplicated; multiplicity is preserved deterministically.
G. source_row_index is the final zero-based position in this canonical expanded source
   sequence; a monotonic sequence equal to source_row_index is assigned from it.

ENGINE-FACING ORDER: the input handed to Nautilus must already be in this canonical order.
Nautilus add_data(sort=True) orders by ts_init; because the canonical order is ts_init
primary, ts_init is consistent between the canonical order and the engine. Implementation
tests MUST prove that, for equal ts_init, the engine's stable ordering preserves the
precomputed canonical tie order (ts_event, event_kind_rank, canonical_row_digest,
canonical_row_bytes). If 1.231.0 cannot prove this via add_data(sort=True), use the
supported add_data(sort=False) path ONLY if an implementation test proves it preserves the
canonical input order. This must never be left implementation-defined.

CANONICAL SEMANTIC ROW SERIALIZATION (frozen normalization contract):
- no binary float anywhere;
- timestamps normalize to exact UTC integer nanoseconds;
- market here means the WP167 pmxt-v2 SOURCE-ROW market field: it accepts the full
  WP167-valid ASCII hex case domain ("0x" + 64 hex, digits 0-9 with a-f OR A-F), and its
  64-hex body normalizes to its validated canonical ASCII "0x" + 64 lowercase-hex form before
  canonical serialization/identity; wrong prefix, wrong length, non-hex, and non-ASCII/Unicode
  lookalikes are rejected. This is distinct from BinaryOptionMarketContext.condition_id, which
  is a repo-owned context input that must ALREADY be canonical "0x" + 64 lowercase-hex and
  rejects alternate case at that public boundary (no silent normalization there);
- asset_id normalizes to validated canonical ASCII decimal digits (no alternate Unicode
  digit forms);
- event_type uses the exact frozen pmxt v2 token (book / price_change / last_trade_price /
  tick_size_change);
- decimal values normalize as exact fixed-point decimal TEXT at the column's documented
  scale (chosen fixed representation; no float, no scientific notation);
- nullable values preserve explicit null;
- side and other enums use their exact validated tokens;
- book bids/asks use the frozen canonical order defined in the PMXT-V2 EVENT-SEMANTIC
  MATRIX (bids sorted strictly by DESCENDING numeric price; asks strictly by ASCENDING
  numeric price; a duplicate price level on one side fails closed), serialized as
  normalized fixed-point decimal text pairs [["price","size"], ...];
- object/dict keys are sorted; array order is preserved only where source semantics make
  order meaningful (book levels by the frozen descending/ascending price rule);
- serialization is UTF-8, ensure_ascii=false, compact separators (",",":"), allow_nan=false;
- hash algorithm SHA-256; canonical bytes are produced by bounded per-row processing.
Reuse a repo-proven canonical outer-JSON mechanic only after normalizing Decimal/datetime/
bytes to text/int first; never feed raw Decimal/datetime/bytes to a canonicalizer that
cannot encode them.

price-level each fail closed. Tests cover malformed JSON, malformed pair, duplicate level,
non-exact decimal, owned-null, and unowned-non-null cases.
