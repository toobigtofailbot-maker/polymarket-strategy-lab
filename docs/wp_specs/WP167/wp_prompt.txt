6. ANALYTICAL PACKAGE, IDENTITY, MANIFEST, EXTERNAL DESCRIPTOR, PMXT
===============================================================================

6.1 materialize_canonical_pit_dataset(record_store_path, dataset_reference,
    output_directory) -> AnalyticalMaterializationResult. It verifies the store via
    the WP163 public API, requires a genuine DatasetSnapshotReference, materializes
    via materialize_dataset_snapshot_reference, requires a valid materialization
    status/mode, preserves ordinary/review role, and never accepts bare caller IDs.
    Derived table families: market_observations, source_snapshots,
    resolution_rule_snapshots, and review_conflicts (to preserve review-role
    semantics). Every row retains canonical identity/provenance fields, family
    fields, and canonical_payload_json. UTC analytical timestamps. No binary float
    for exact decimal identity fields.
6.2 Analytical identity: logical analytical dataset identity is derived from the
    analytical schema/version, source kind, canonical DatasetSnapshotReference id or
    ExternalDatasetDescriptor id, materializer/importer semantic version, ordered
    tables/partitions, row counts, and deterministic bounded streaming logical row
    digests in explicit row order. It is never defined by physical Parquet bytes.
    Same logical input across Windows/Linux yields the same logical row digest and
    logical dataset id; physical Parquet bytes may differ. Physical materialization
    evidence records the relative file, exact file SHA-256, byte length, schema
    fingerprint, row count, logical row digest, and library/Python versions.
6.3 Analytical manifest: frozen AnalyticalPartitionManifest and
    AnalyticalDatasetManifest carry the fields above plus pyarrow/duckdb/polars/
    python versions, advisory_only=True, and no_execution_authority=True. Forbidden
    from identity/output: absolute local paths, environment values,
    username/hostname, wall-clock creation time, secrets, and raw exception strings.
6.4 External descriptor: a frozen ExternalDatasetDescriptor with schema id/version,
    external_dataset_id, provider, dataset name/version, source_class, UTC
    coverage_start/end, source objects (stable object name, exact source SHA-256,
    byte length, partition/hour identity), source schema fingerprint, timestamp
    semantics, event types, gap policy, quality tier, importer id/version, license,
    attribution, advisory_only=True, no_execution_authority=True. No absolute local
    path in identity/output. Source classes: NATIVE_OFFICIAL_CAPTURE,
    OFFICIAL_HISTORICAL_EXPORT, THIRD_PARTY_NATIVE_FRAME_ARCHIVE,
    DERIVED_RESEARCH_DATASET, BENCHMARK_ONLY. pmxt v2 MUST be
    THIRD_PARTY_NATIVE_FRAME_ARCHIVE.
6.5 pmxt v2 adapter (PMXT_V2_POLYMARKET_ORDERBOOK_ARCHIVE): input is explicitly
    supplied LOCAL Parquet file paths only. No URL retrieval, HTTP, Polymarket API,
    object-store SDK, or downloader. For each file compute the exact SHA-256 and
    byte length, inspect the Arrow/Parquet schema, validate required columns/types,
    event types, UTC timestamps, and decimal/side semantics, record the schema
    fingerprint, and reject unsupported material schema drift. Never require
    whole-file Python materialization; use metadata/lazy/batched access with a
    default max row batch of 131072. Tests generate representative tmp_path Parquet
    fixtures only; no large committed fixtures; no duplicate archive copy.
6.6 DuckDB proves SQL over repo-derived PIT Parquet and registered pmxt external
    Parquet: COUNT, min/max timestamp, group count, deterministic filter. Polars
    proves scan_parquet/lazy scan, projection, filter, group/count, timestamp and
    decimal/null semantics. DuckDB and Polars must agree on total rows, one grouped
    count, and timestamp min/max for the same fixture.
6.7 Parquet writer rules: PyArrow explicit schema, deterministic column order,
    deterministic row sort, UTC, no random ids, no wall-clock metadata, no
    environment metadata, stable compression (zstd), stable partition naming, schema
    v1 only, no implicit schema union/evolution.
6.8 Result/error safety: frozen typed results and a closed error vocabulary that at
    minimum distinguishes ANALYTICAL_INPUT_INVALID, ANALYTICAL_CANONICAL_STORE_INVALID,
    ANALYTICAL_REFERENCE_INVALID, ANALYTICAL_MATERIALIZATION_FAILED,
    ANALYTICAL_SCHEMA_INVALID, ANALYTICAL_IDENTITY_MISMATCH,
    ANALYTICAL_FILE_INTEGRITY_INVALID, ANALYTICAL_QUERY_VALIDATION_FAILED,
    EXTERNAL_DESCRIPTOR_INVALID, EXTERNAL_SOURCE_FILE_INVALID,
    EXTERNAL_SOURCE_SCHEMA_INVALID, EXTERNAL_SOURCE_HASH_INVALID,
