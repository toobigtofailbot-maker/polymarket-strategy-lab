4. RESEARCH-METHODOLOGY PRINCIPLES TO ENFORCE
===============================================================================

The implementation must encode these principles rather than merely document them.

A. Preregistration before result inspection
- Hypothesis, target, metrics, exclusions, thresholds, split policy, baseline, parameters,
  multiplicity policy, and failure criteria are frozen before OOS result evaluation.
- A plan changed after OOS exposure is a NEW experiment identity, never a mutation of the
  original preregistration.
- Planned and exploratory analyses must be distinguishable.

B. Time-series leakage control
- Random IID train/test splitting is NOT an acceptable default for market-time-series data.
- Split assignment must be deterministic and time-aware.
- Future-horizon labels and overlapping information windows require purge logic around
  partition boundaries.
- An explicit embargo/buffer policy must exist where serial dependence or overlapping
  horizons can contaminate adjacent samples.
- Feature information availability must never exceed the sample's decision/as-of time.
- Label availability must remain distinct from target/event time.

C. Group/entity leakage control
- Every split plan must explicitly declare its group-isolation policy.
- The system must never silently assume that samples from the same market, event, relation
  component, wallet/entity, or other declared leakage group are independent.
- If the declared policy requires group exclusivity and the requested split cannot satisfy
  it, fail closed rather than silently weaken the policy.

D. Multiple-testing / researcher-degrees-of-freedom accounting
- Related trials belong to a deterministic experiment family.
- Every preregistered trial counts, including negative, invalidated-after-run, and
  inconclusive trials where the attempt genuinely consumed evaluation information.
- A failed experiment cannot disappear or be relabeled as if it never happened.
- A family cannot silently reset its trial count merely because a new parameterization,
  threshold, feature subset, or naming variant is tried.
- The correction/accounting policy is preregistered. WP170 need not invent statistical
  significance calculations that it cannot truthfully validate.

E. OOS is a controlled evidence state, not a filename
- OOS data is data not used for hypothesis formation, feature/threshold selection, tuning,
  or acceptance-rule selection.
- The repo-controlled workflow must seal the OOS partition before tuning is complete.
- The first qualified OOS release/evaluation is recorded immutably.
- Subsequent OOS reuse is explicitly labeled reused/diagnostic and cannot masquerade as
  pristine first-look OOS evidence.
- The software must state its limitation honestly: it can enforce and audit the repo-owned
  workflow, but it cannot cryptographically prove a human never viewed the same information
  outside the controlled workflow.

F. Negative evidence is first-class evidence
- Negative and inconclusive outcomes are retained append-only.
- No deletion, overwrite, "best run only" view, or winner-only persistence is allowed as the
  authoritative experiment record.
- A positive OOS criterion result in WP170 is at most "OOS criteria met / uncOSTED".
  It is NOT "alpha", "profitable", "tradeable", or "execution-ready".

9.2 IMMUTABLE FEATURE-DEFINITION IDENTITY

A feature definition must be immutable and content-addressed.

It must freeze enough information to determine what information the feature is allowed to use:
- stable feature name/version;
- semantic description;
- exact source field/record-family dependencies;
- deterministic parameters;
- lookback/window rule;
- source-time / availability-time rule;
- missing-data policy;
- transformation/version or code-identity reference;
- no-future-information rule.

Do not serialize arbitrary Python callables, executable code, pickles, lambdas, or dynamic
plugins into the registry.

Feature-definition changes create a new feature_definition_id.

9.3 IMMUTABLE LABEL-DEFINITION IDENTITY

A label definition must freeze:
- stable label name/version;
- prediction target;
- horizon / target-time rule;
- resolution/outcome source rule;
- label availability-time rule;
- censoring/missing/ambiguous outcome rule;
- deterministic parameters;
- version/code reference.

Target time and label availability time are separate fields. A resolved outcome becoming
known later must never be treated as information available at the earlier prediction time.

Label-definition changes create a new label_definition_id.

9.4 SAMPLE / RESEARCH-DATASET MANIFEST

The experiment OS must create a deterministic sample-level manifest sufficient to audit
information timing and partition assignment.

Each sample must have a stable sample identity and bind at minimum:
- dataset/snapshot identity;
- source record/logical row identity or deterministic source-membership digest;
- market identity;
- event/related-group identity where available;
- explicit leakage_group_id or explicit declared no-group-isolation policy;
- decision/as-of timestamp;
- maximum feature information availability timestamp;
- target timestamp;
- label availability timestamp;
- feature definition set identity;
- label definition identity;
- deterministic sample content/lineage digest.

Fail closed if:
- feature availability is after decision/as-of time;
- time fields are noncanonical or inconsistent;
- duplicate sample identity has conflicting content;
- a source identity is unknown/tampered;
- required group policy is absent;
- the manifest cannot be deterministically reproduced.

Actual large feature matrices do not need to be copied into the registry. The registry may
store exact identities/digests and deterministic membership metadata while existing
analytical datasets remain the data substrate.

9.5 DETERMINISTIC TEMPORAL SPLIT PLAN

At minimum, support a deterministic three-role research split:
- FORMATION / DISCOVERY
- SELECTION / VALIDATION / TUNING
- OUT_OF_SAMPLE

The exact closed vocabulary may use one canonical label per role but must preserve these
semantics.

The split plan must freeze:
- split-plan ID/version;
- UTC boundaries;
- deterministic ordering/tie-breaks;
- label-horizon purge rule;
- embargo/buffer rule;
- group-isolation policy;
- explicit inclusion/exclusion policy;
- empty/insufficient-partition behavior;
- deterministic split assignment hash.

The implementation may additionally support expanding walk-forward folds inside the
formation/selection area if it can do so cleanly within scope. It must NOT weaken the single
untouched final OOS holdout.

Default behavior for temporal market data must not be random IID splitting.

Purging:
- if a formation/selection sample's information/label interval overlaps a later
  selection/OOS evaluation interval in a way that would leak future outcome information,
  exclude it according to the locked purge rule.

Embargo:
- enforce the preregistered post-boundary buffer when configured/required.

Group isolation:
- every split plan explicitly declares whether groups are exclusive across partitions;
- if exclusive, the same declared leakage group cannot appear in multiple roles;
- an impossible grouping/boundary combination fails closed.

No sample can belong to more than one final partition.

9.9 EXPERIMENT FAMILY / MULTIPLE-TESTING LEDGER

Every preregistered experiment must belong to a deterministic experiment family or to an

The family record must freeze:

- cohort/target/metric-family semantics;
- correction/accounting policy;
- trial ordering;

Rules:
- every trial that reaches the registered evaluation boundary is retained;
- negative and inconclusive trials count;
- parameter/threshold/feature variants do not silently reset the family;
- identical duplicate registration is idempotent;
- conflicting family/trial identity fails closed;

9.10 SEALED OOS LIFECYCLE

Implement an explicit deterministic product lifecycle distinct from the WP authorization
state machine.

The exact state vocabulary is frozen in the certified product contract, but semantics must
include:

1. preregistration locked;
2. formation work may be recorded;
3. selection/tuning work may be recorded;
4. selection is irreversibly closed for this experiment identity;
5. OOS remains sealed until that close;
6. first OOS release/exposure produces an immutable exposure receipt;
7. first OOS evaluation produces one immutable first-look OOS evidence record;
8. any later OOS evaluation/reuse is explicitly classified as reused/diagnostic;
9. experiment closes with negative, inconclusive, or OOS-criteria-met-uncosted status.

Required invariants:

11. ADVERSARIAL ACCEPTANCE CONTRACT
===============================================================================

Do not call WP170 complete because happy-path tests pass.

The final implementation must have direct tests or deterministic proof for all applicable
cases below. Consolidate them into a small number of focused test modules rather than one
file per bullet.

IDENTITY / IMMUTABILITY
- identical semantic input under different mapping insertion order -> identical ID;
- included field mutation -> different ID;
- excluded local/path/time-of-write metadata -> does not alter logical ID;
- explicit null vs omitted where contract distinguishes them -> correct deterministic result;
- conflicting same ID -> fail closed;
- immutable frozen result objects / no caller mutable reference retained.

DATASET / SAMPLE LINEAGE
- valid existing DatasetSnapshotReference binds successfully;
- tampered/unknown dataset reference rejects;
- analytical logical dataset identity is preserved;
- physical Parquet byte difference alone does not redefine logical experiment dataset;
- duplicate source membership handled deterministically;
- invalid/quarantined/review-conflict input cannot silently become ordinary data.

TEMPORAL LEAKAGE
- feature availability after decision time rejects;
- future outcome field in a feature-source declaration rejects;
- label availability is not confused with target time;
- boundary sample whose label interval overlaps OOS is purged;
- configured embargo is actually enforced;
- timestamp equality edge cases are explicitly tested;
- noncanonical timezone/timestamp forms reject or normalize exactly as certified.

PARTITION LEAKAGE
- no sample appears in multiple final roles;
- split assignment is deterministic under input reordering;
- declared group-exclusive policy prevents same group crossing roles;
- impossible group/time split fails closed;
- empty or too-small OOS fails according to the locked contract;
- no random split default exists.

PREREGISTRATION
- locked preregistration round-trips with identical ID;
- post-lock threshold mutation yields new experiment identity or rejects mutation;
- post-lock feature set mutation yields new identity;
- post-lock label mutation yields new identity;
- post-lock split mutation yields new identity;
- post-lock baseline mutation yields new identity;
- result evidence cannot precede preregistration.

OOS SEAL
- OOS release before selection close rejects;
- first OOS release writes one immutable exposure receipt;
- second release does not become another pristine first look;
- first-look OOS evidence is distinct from reused diagnostic evidence;
- after OOS exposure the experiment cannot return to an unseen state;
- lifecycle replay/out-of-order transition/tamper rejects;
- a spec variant after OOS is a new trial/experiment, not an overwrite.

MULTIPLE TESTING / NEGATIVE RETENTION
- every registered evaluated trial increments/appears in family accounting;
- negative trial remains visible;
- inconclusive trial remains visible;
- a renamed parameter variant cannot overwrite an old trial;
- identical retry is idempotent rather than double-counted;
- no winner-only authoritative query;
- correction/accounting policy is immutable after preregistration.

BASELINE
- candidate and baseline evidence must reference identical registered partition membership
  where baseline comparison is required;
- candidate criterion met but baseline rule failed -> overall criterion does not pass;
- baseline identity mutation after preregistration -> new experiment identity.

REGISTRY TRUST BOUNDARY
- wrong file suffix/path class where prohibited;
- missing parent directory where prohibited;
- symlink/hardlink behavior matches the chosen safe store pattern;
- foreign SQLite schema rejects without mutation;
- schema/index tamper rejects;
- history-chain tamper rejects;
- invalid state token rejects;
- duplicate conflicting record rejects;
- store row/byte/object bounds actually trigger;
- exact idempotent reappend at bound succeeds if no new rows/bytes are added;
- load-and-verify validates complete history, not only current cache.

SAFE OUTPUT
- invalid raw caller strings never appear in errors/receipts;
- local absolute path never appears in error/result metadata;
- exception text/tracebacks are not exposed through closed result surfaces;
- forbidden authority/trading interpretation scan covers all public result serializers.

REPRODUCIBILITY
- semantically identical preregistration produces identical canonical bytes/hash/id;
- sample input reorder produces same logical sample set/split assignment;
- deterministic seed/parameter identity is bound;
- code/repo version is bound;
- final run receipt can be independently recomputed from its committed inputs.

SUCCESSOR BOUNDARY
- no COST_ADJUSTED_RESULT claim;
- no paper/live/strategy/execution/Hermes/dashboard/network/dependency authority;
- no current-WP test can pass by merely checking prose while the implementation violates the
  invariant it claims.
