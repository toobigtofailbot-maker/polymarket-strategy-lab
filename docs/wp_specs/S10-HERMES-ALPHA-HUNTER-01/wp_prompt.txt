# 1. Objective

Build the shortest complete research/intelligence loop that, in ONE finite foreground
invocation, discovers markets in at least two genuinely supported categories, derives an
independent source-backed probability with explicit uncertainty for each supported market,
checks current public venue mechanics (identity, rule, tick, minimum, depth, fee), computes
an ESTIMATED after-cost margin for a fixed research quantity, states whether a hypothetical
USD 2-5 fee-inclusive order could satisfy the verified venue rules, ranks comparable research
candidates deterministically with a complete denominator funnel, runs budgeted controlled Hermes
research on the provisional candidates BEFORE final selection so that validated, source-backed,
origin-labelled Hermes findings can change the research tier (never the probability, bounds or
margins), and records immutable lineage in the existing PIT store and Alpha Factory registry.
With no Hermes budget the run is labelled `PUBLIC_SCREENER_NO_HERMES`: an honest multi-category
screener, not proof of Hermes inference. Amendment A1 (Karl, 2026-10-27) added the Hermes
influence and the small-order indication; scope stays seven files.

The two categories are fixed by pre-draft inspection evidence (PRE-DRAFT_INSPECTION.md):

- SPORTS_NBA_MONEYLINE: unchanged merged method `espn-nba-pregame-v1`
  (`tools/alpha/run_shadow_alpha_cycle.py` `rule`, `matched_event`, `probability`).
- WEATHER_US_DAILY_RAIN: Gamma daily event `where-will-it-rain-on-<month>-<day>-<year>`
  (US cities; rule = NWS Daily Climate Report CLI measurable precipitation >= 0.01 in,
  trace is No, climate day midnight-to-midnight LOCAL STANDARD TIME for the named ICAO
  station, last CLI version before 2:00 PM ET the next day governs, no figure means No).
  New method `nws-gridpoint-pop-climate-day-v1` over public `api.weather.gov` gridpoint
  `probabilityOfPrecipitation`.

Crypto short-duration is excluded: no defensible independent source-to-probability method
exists in the repository. Protocol-V2 markets (`positionIds` equal to `clobTokenIds`, or a `polyv2-` market or event slug) are
rejected as PROTOCOL_UNSUPPORTED; this WP does not guess V2 identity or size semantics.

This is not a strategy, qualification, paper, Gate C or execution package. Valid NO_TRADE is a
successful outcome. Proven profitability, calibrated probability, guaranteed fill and real
positive P&L are never claimed.

# 6. Implementation contract

Interface (absolute paths only; no defaults, no auto-discovery):
`run --scratch-dir ABS --alpha-registry ABS --categories nba,rain
 [--research-budget ABS_JSON --hermes-executable ABS --hermes-home ABS]` and
`verify --scratch-dir ABS`. `--alpha-registry` must be an existing verified Alpha Factory
registry (the operator never initializes it). The three Hermes flags are all-or-nothing; any of
them without the others, or present with a zero budget, is a usage error. Scratch config is
created on first `run` and must match byte-for-byte afterwards. One invocation = one
STARTED-first operation under the kernel lock. Public-acquisition ceilings: 64 GETs, 180 s
wall clock, NBA <= 8 events, rain <= 6 markets. The Hermes phase is bounded separately by
runs x per-run `max_wall_seconds`. Clocks: `anchor_utc_date` is taken once at operation start
and fixes the rain target dates; `cutoff` is taken after all source and Gamma GETs and before
the CLOB book GETs, which are fetched last; book age is measured against the book receipt time
and must be <= 30 s at the economics evaluation.

6.1 Fixed public GET allowlist (exact templates; no redirect; anything else refused):
- NBA: shadow `DISCOVERY_URL`, `ESPN` scoreboard/summary templates, native CLOB book URL.
- Rain: `https://gamma-api.polymarket.com/events/slug/where-will-it-rain-on-<month>-<d>-<yyyy>`;
  `https://api.weather.gov/stations/K[A-Z0-9]{3}`;
  `https://api.weather.gov/points/<lat 4dp>,<lon 4dp>` (coordinates rounded half-even to 4 dp,
  then trailing zeros and a trailing dot stripped; non-normalized forms trigger a 301 that
  NoRedirect turns into SOURCE_UNAVAILABLE);
  `https://api.weather.gov/gridpoints/[A-Z]{3}/[0-9]{1,3},[0-9]{1,3}` (must equal the points
  document `forecastGridData`); native CLOB book URL.
Rain target dates: the two dates after `anchor_utc_date` (two event GETs). Markets
are taken in ascending (target_date, gamma_market_id) order, first six that pass the rule and
protocol filters. Categories are acquired and capped independently, so one cannot crowd out
the other.

6.2 Rain probability (method `nws-gridpoint-pop-climate-day-v1`, Decimal only). Window =
`climate_day_window(target_day, standard_utc_offset_minutes(tz, target_day))`. Require
`probabilityOfPrecipitation.uom == "wmoUnit:percent"`, every value an integer 0..100 with
p = value/100 (else PROBABILITY_INVALID); gridpoint `updateTime` <= cutoff and cutoff -
`updateTime` <= 6 h (else SOURCE_STALE / LOOKAHEAD); cutoff < window start (else
EVENT_OR_CLIMATE_DAY_STARTED_UNSUPPORTED); overlapping intervals cover the whole window (else
SOURCE_COVERAGE_INCOMPLETE); every overlapping interval start and both window edges fall on a
whole UTC hour (else SOURCE_COVERAGE_INCOMPLETE). With overlapping intervals i (value p_i, overlap hours h_i,
duration hours d_i):
- lower = max p_i over intervals FULLY inside the window, or 0 if none;
- upper = min(1, sum p_i * ceil(h_i));
- point = 1 - prod(1 - p_i * h_i / d_i), clamped into [lower, upper].
The upper bound holds whether a run-length value is an interval PoP or a repeated hourly PoP.
Labels: `uncertainty_kind=BOUNDS_OVER_POP_INTERVALS`,
`interval_semantics=RUN_LENGTH_VALUE_ASSUMED_INTERVAL_POP`,
`point_assumption=INTERVAL_INDEPENDENCE_AND_UNIFORM_WITHIN_INTERVAL`,
`spatial_assumption=GRID_CELL_EQUALS_STATION`,
`resolution_risk=CLI_PUBLICATION_DEADLINE_UNMODELLED`,
`accumulation_risk=SUB_THRESHOLD_INTERVAL_SUMS_UNMODELLED`, `calibration=UNPROVEN`.
For the NO token: p_no = 1 - point, lower_no = 1 - upper, upper_no = 1 - lower.

6.3 NBA probability: unchanged `probability()`; the payout hull keeps the 0.5 cancellation value.

6.4 Venue economics (taker only; one generalized function). Protocol-V2 (`positionIds` equal to
`clobTokenIds`, or a `polyv2-` market or event slug) -> PROTOCOL_UNSUPPORTED before any book GET.
Live check 2026-10-27 (amendment A3): all 55 open NBA moneyline CTF markets carry `positionIds`
that differ from `clobTokenIds`, while the `polyv2-` rain twin has them equal; mere presence of
`positionIds` is therefore not a V2 marker. Require Gamma/CLOB identity,
equal tick, neg-risk equality, active/accepting/order-book flags, two-sided book, prices on
tick, book age <= 30 s. Fixed research quantity q = 10 shares, never scaled up. Minimum order
follows repo truth exactly as `evaluator._minimum_order` (S10-LIVE-ORCH-01 repair): both values
must exist, q >= CLOB `min_order_size` (shares) AND fill notional >= Gamma `orderMinSize`
(`gamma_min_order_notional_usd`, USD) (else VENUE_MINIMUM_OR_DEPTH_UNSUPPORTED). The official
order docs describe size in shares; that semantic dispute is recorded in
`docs/deferred_items_log.md`, not resolved by reinterpretation here. Full q must fill within
best-ask depth. Fee: `fees_enabled` absent or `feeSchedule` incomplete -> FEES_UNKNOWN;
`fees_enabled` false -> fee 0; otherwise native `_taker_fee` with the Gamma rate and exponent,
quantized up to 0.00001. When the Gamma rate differs from the documented category taker rate
(docs.polymarket.com/trading/fees, read 2026-10-27: Sports 0.05, Weather 0.05) the row carries
`FEE_RATE_SOURCE_DISAGREEMENT`, the point margin uses the Gamma fee and the conservative margin
uses the larger of the two fees computed with the Gamma exponent. Residual 0.005/share.
`estimated_after_cost_margin = q*p - notional - fee - residual`; `conservative_margin` uses the
lower payout bound and larger fee; `optimistic_margin` the upper bound. All Decimal.
`fill_probability = null` (`UNMEASURED`); `restricted` recorded as `restriction_observed`.
Expected consequence documented in the contract: with q = 10 and a USD 5 Gamma minimum, tokens
priced below about 0.50 fail the notional minimum, so many NO/underdog tokens are
VENUE_MINIMUM_OR_DEPTH_UNSUPPORTED; this follows repo truth and is reported, not worked around.

6.4b Small-order fit (RESEARCH-ONLY hypothetical; not execution feasibility). For each
RESEARCH_CANDIDATE token, with a = best ask and D = size at the best-ask level (the same single
level the 10-share economics sweeps), the cap fee is the larger of the Gamma-rate fee and the
documented-rate fee when FEE_RATE_SOURCE_DISAGREEMENT is set, else the Gamma-rate fee. Search
domain: q_s in {0.01 k : 0 < q_s <= min(D, floor_0.01(5.00 / a))} (size decimals 2 for every
tick, mirroring `gate_c._SDK_ROUNDING_BY_TICK`, restated as a constant, not imported). Choose
the largest q_s in that domain with `cost(q_s) = a*q_s + cap_fee(q_s) <= 5.00` (cost is monotone
in q_s; binary search). Closed sub-reasons, first failing in order:
SMALL_ORDER_DEPTH_BELOW_FLOOR (no q_s exists, or cost(q_s) < 2.00);
SMALL_ORDER_GAMMA_MIN_NOTIONAL_NOT_MET_WITHIN_CAP (a*q_s < Gamma `orderMinSize`);
SMALL_ORDER_CLOB_MIN_SHARES_NOT_MET_WITHIN_CAP (q_s < CLOB `min_order_size`);
SMALL_ORDER_MARGIN_NONPOSITIVE (`small_order_estimated_margin = q_s*p - a*q_s - gamma_fee(q_s) -
0.005*q_s <= 0`). `small_order_conservative_margin` uses the lower payout bound and the cap fee,
exactly as `conservative_margin` does in 6.4. Expected consequence, documented in the contract:
with a USD 5 Gamma minimum and any positive cap fee no fee-inclusive order <= USD 5 can fit, so
the selected set is often empty; this is reported, never worked around. Output
fields: `small_order_fit`, `small_order_reason`, `small_order_shares`, `small_order_cost_usd`,
`small_order_estimated_margin`, `small_order_conservative_margin`, labelled
`HYPOTHETICAL_RESEARCH_ONLY_FULL_FILL_ASSUMED_FILL_PROBABILITY_UNKNOWN`. The 10-share figures stay
as the numeric-parity research fixture. No live policy or risk constant is read or changed.

NO_CONTRARY_EVIDENCE_REPORTED if it is empty and the run is valid; RESEARCH_FAILED on any
controller failure; NOT_RUN otherwise. Hermes episode `result_state`: NO_EDGE_CURRENTLY if
`evidence_against` non-empty, else RESEARCH_SUPPORTIVE if `evidence_for` non-empty, else
DATA_INSUFFICIENT if `known_missing_data` non-empty, else no episode (RESEARCH_FAILED); its
`predecessor_episode_id` is the deterministic episode appended for the same market in the same
run. Influence (applied before final selection, deterministic): a finding influences the research
tier only if its origin is `REAL_PROVIDER_REPORTED`, the controller run and revalidation
succeeded, its receipt `end_utc` lies between the operation start and the moment influence is
evaluated, its request binds this token's gamma_market_id/condition_id/token_id/category, and the
hunter source mapper yields >= 1 usable source. Then
CONTRARY_EVIDENCE_REPORTED -> tier 2 (HERMES_CONTESTED); NO_CONTRARY_EVIDENCE_REPORTED with
non-empty `evidence_for` -> tier 0 (HERMES_CORROBORATED); anything else -> tier 1. Every other
finding (fixture/unverified origin, no usable source, failed run) is recorded with
`influence=NONE` and the reason, and leaves tier 1. Hermes never changes p, bounds, margins,
small-order fields or the NO_TRADE classification, and never makes a NO_TRADE token selectable.
Manifest `run_mode`: `PUBLIC_SCREENER_NO_HERMES` (no budget), `HERMES_ATTEMPTED_NO_INFLUENCE`, or
`HERMES_INFLUENCED`; `hermes_alpha_hunter_milestone` is `SATISFIED_REAL_PROVIDER_INFLUENCE` only
when >= 1 REAL_PROVIDER_REPORTED finding changed a tier, else
`UNSATISFIED_REAL_INFERENCE_NOT_DEMONSTRATED`.

6.8 Records and identity. OpportunityCandidate inputs are a pure function of (category,
method_id, gamma_market_id, condition_id, rule_text_sha256), with rule_text_sha256 also in the
