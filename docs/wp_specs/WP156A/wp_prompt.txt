===============================================================================

RECORD_VERSION_HASH_COLLISION_OR_MISMATCH. It is permanently consumed.

Current WP156 _record_fingerprint(record) embeds the already-serialized
record.canonical_payload_json as one string node in a new canonical_json_bytes outer
mapping. canonical_json_bytes correctly limits every semantic string node to 4096,
while an otherwise valid payload tree may serialize above 4096 bytes when each inner
string, sequence, node, and total-byte limit remains valid. The builder can therefore
accept the record and the batch fingerprint can reject it.

Before changing production, construct an ordinary authoritative ORDER_BOOK record in
the existing WP156 focused test file. Require public builder validity, true payload-tree
bounds, len(canonical_payload_json) > 4096, and the exact current batch failure shape:
invalid, error_codes exactly RECORD_VERSION_HASH_COLLISION_OR_MISMATCH, accepted empty,
quarantined empty. If that does not reproduce, stop ROOT_CAUSE_NOT_REPRODUCED and make
no semantic fix.

The final green test must preserve both sides: the same record remains ordinarily valid;
the legacy wrapper canonical_json_bytes({canonical_payload_json: complete string}) raises
exactly PAYLOAD_STRING_LIMIT_EXCEEDED; corrected validate_record_batch succeeds.
