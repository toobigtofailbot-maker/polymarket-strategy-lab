1. TRIGGER / OBJECTIVE
===============================================================================

Trigger (real Phase B, deployed cb82114 release): one direct curl eth_chainId request from the same
host to https://polygon.drpc.org returned HTTP 200 / 0x89 in 0.109 s, while the canonical urllib
public smoke failed twice (about 22 minutes apart) with an immediate NETWORK_TIMEOUT after about
1.1 s and zero Polygon raw rows; Gamma/CLOB/Data HTTP and the WebSocket were healthy. The mixed
window was therefore invalid and coexistence was EXECUTION_HOST_INCONCLUSIVE. Not a capacity failure.

Defect (src/data_layer/polymarket/market_truth_onchain.py _default_rpc_transport): no explicit
User-Agent although WP169 requires fixed Accept/Content-Type/User-Agent production values, and every
urllib exception including HTTPError collapses to NETWORK_TIMEOUT.

Objective: repair the WP169 Polygon public RPC production transport so it uses the already-certified
fixed User-Agent and preserves HTTP responses for existing non-2xx handling instead of collapsing
HTTPError into NETWORK_TIMEOUT, without changing provider authority, RPC methods, credentials,
trading authority, or live/economic behavior.

Required behavior:
- headers exactly Content-Type: application/json, Accept: application/json,
  User-Agent: wp169-public-market-truth/1.0; no caller/environment/credential headers;
- urllib HTTPError -> (status, headers, body) -> existing _rpc_call non-2xx rule -> RESPONSE_INVALID;
- DNS/connect/TLS/socket timeout/other transport exception -> NETWORK_TIMEOUT;
- no retry, redirect or fallback logic added; provider allowlist drpc only; method allowlist,
  byte bounds, JSON parsing, chain check, source ids/cursors, checkpoint/reorg semantics and
  public signatures unchanged; no new dependency.
