## 1. Objective

The 2026-10-20 read-only pre-publication audit (finding H1) proved that the committed
`.gitleaks.toml` defines zero detection rules: it holds only a legacy `[allowlist]` table and no
`[extend]` table, and gitleaks auto-loads it from the scanned source root. Every
`gitleaks git --redact` run by `tools/security/run_available_security_checks.py` since WP15
therefore passed vacuously. A synthetic token was detected only with the file removed. The legacy
allowlist `paths` entry also excluded all of `docs/deferred_items_log.md`.

Restore real detection with the smallest correction:

1. extend the embedded default rules through the official `[extend] useDefault = true` mechanism;
2. keep only the exact WP14-D002 line regex as a prose exclusion and drop the whole-file path;
3. list each manually classified historical fixture finding by exact fingerprint in `.gitleaksignore`;
4. prove detection with a deterministic regression and negative matrix;
5. let the deterministic spec guard govern exactly the two repository-root secret-scan
   configuration paths as `local_offline_tooling` — today it maps no root non-dependency path and
   rejects any package containing them with `AUTHORITY_CONTRADICTION`.

The security runner, workflows and CI matrix stay unchanged. PR #246 is not modified.

### B. `.gitleaksignore`

directory, rule or wildcard entry. A future finding must be fixed or classified individually.

look-alikes (`.gitleaks.toml.bak`, `gitleaks.toml`, `.gitleaks`), nested copies and every other
unmapped root path remain `AUTHORITY_CONTRADICTION`.

literal. Binary-backed tests skip when no gitleaks binary is available. A skip is reported, never
counted as detection evidence.

results are not detection evidence. The deferred log records that hosted CI does not install
