2. CONFIRMED ROOT CAUSE
===============================================================================

Merged source currently contains:

  _SEMVER_TOKEN = re.compile(r"\b(\d+\.\d+\.\d+)\b")

and:

  def parse_hermes_version(reported):
      ...
      match = _SEMVER_TOKEN.search(reported)
      return match.group(1) if match else None

Exact pinned Hermes:
  NousResearch/hermes-agent
  version: 0.21.3
  tag: v2026.9.14
  commit: 345cd2b057a452236de401d3534b8502a7465e8d

Exact tagged source defines:
  __version__ = "0.21.3"
  __release_date__ = "2026.9.14"

Exact tagged banner path emits the branded form:

  Hermes Agent v0.21.3 (2026.9.14)

and may append an upstream/local git suffix.

Why merged parser fails:
- regex begins at the first digit and requires a word boundary before it;
- in "v0.21.3", both "v" and "0" are regex word characters;
- therefore there is NO word boundary before the package-version digit;
- the package version is skipped;
- the later release date "2026.9.14" is preceded by a non-word delimiter, so it is selected;
- actual observed result:
    reported_semver = 2026.9.14
  even though:
    version_text_contains_0_21_3 = true.

This is a merged deterministic software defect.

Existing tests missed it because they used synthetic:
  hermes-agent 0.21.3

rather than the exact real banner:
  Hermes Agent v0.21.3 (2026.9.14)

No controller, runner, provider, Firecrawl, OAuth, dependency, or upstream-Hermes defect is currently established.
